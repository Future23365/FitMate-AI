# 2026-05-31 本地匿名 Cookie 与登录弹窗

## 原方案问题

上一版本地匿名鉴权把“进入应用”和“创建匿名用户”绑定在一起。应用挂载时如果没有本地 token，会先显示一个替换页面的登录 gate；匿名 token 存在 `localStorage`，统一请求层再把它拼到 `Authorization: Bearer <token>`。这让页面无法先正常进入，也把凭证暴露给客户端脚本。

## 调整思路

本次把匿名凭证收口到服务端 HttpOnly cookie。页面启动不再主动创建匿名用户，只有私有接口返回明确未认证语义时，客户端请求层才广播 auth-required 事件，由 `LocalAuthProvider` 在当前应用布局内打开 shadcn/ui Dialog。

## 关键改动

- `POST /api/auth/local-anonymous` 成功后通过 `Set-Cookie` 写入匿名 auth cookie，响应体只返回最小用户摘要，不返回 token。
- `requireCurrentUser(request)` 从请求 cookie 读取并校验 token，缺少、过期或无效 token 统一映射为 `401 unauthenticated`。
- 客户端请求层不再读取 `localStorage`，也不再注入 `Authorization`，只识别 `401 unauthenticated` 和明确未认证语义的历史 `403`。
- `LocalAuthProvider` 首次渲染直接展示页面；收到 auth-required 后打开布局内 Dialog，登录成功后关闭弹窗并依赖 cookie 处理后续请求。
- 设置页“重置本地用户”调用服务端 `DELETE /api/auth/local-anonymous` 清除 cookie，不删除旧匿名用户服务器数据。

## 结果

本地匿名鉴权的安全边界更接近正式会话模型，页面不会因为缺少匿名凭证被整页替换，真实 forbidden 权限错误也不会误触发登录弹窗。
