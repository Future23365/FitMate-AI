# Agent 活动状态条

时间：2026-06-02 01:01:15 +0800

## 背景

`/api/chat` 已经切到 Tool-first Agent 主链后，一次请求会经历上下文构建、模型决策、工具查询、训练生成、校验、保存、Response Writer 投影和 summary 收尾。旧页面只在消息气泡里展示“正在思考”，无法说明系统正在执行哪类编排工作；当动作库查询或训练 artifact 保存耗时较长时，用户容易误以为请求卡住。

直接展示 `/dev/ai-traces` 的 step title、toolName、resource id 或模型 payload 不合适。这些字段服务开发诊断，粒度过细，也可能把 prompt、工具参数、候选池或 trace 细节暴露到生产 UI。

## 调整思路

新增一个生产聊天页专用的 `agent_activity` stream 事件，只输出 `stage`、`status`、`messageKey`、`sequence` 四类 UI 安全字段。服务端在 Agent 主链稳定边界发出粗粒度阶段，前端只用白名单中文文案和图标映射展示，不信任服务端自由文本。

状态条放在输入框上方，作为当前请求的短生命周期 UI 状态。它不会写入 `ChatMessage`、聊天历史、conversation summary、conversation context 或 artifact payload。旧“正在思考”气泡被状态条吸收，避免一个请求期间出现两个 loading 提示。

## 关键改动

- 新增共享 `AgentActivityStage` / `AgentActivityPayload` 合同，并在 `features/chat/types.ts` 暴露 `agent_activity` stream 事件类型。
- `/api/chat` 的 Agent response stream 改为在 stream start 内执行主链，使 `preparing_context` 可以先于模型和工具耗时工作发给前端。
- `runAgentOrchestrator` 新增用户安全 activity 回调，把 `searchExercises`、artifact 读取、draft 生成、validator / policy、revision 保存等内部工具压缩成粗粒度阶段。
- `useChatController` 新增 `agentActivity` 状态，按 `sequence` 防止乱序覆盖，并在 `done`、`error`、超时、abort、hash 切换、加载历史会话和新建会话时清理。
- 新增 `AgentActivityIndicator`，在输入框上方展示中文阶段文案、Material Symbols 图标、克制动效、`aria-live="polite"` 和 `prefers-reduced-motion` 边界。
- `saveChatConversation` 改为显式白名单持久化消息字段，避免短生命周期 UI 字段被误带入聊天历史。

## 结果

- 首个用户可见 `content` 前至少有一个 `agent_activity` 事件。
- activity payload 不包含 prompt、raw model output、tool payload、resource id、trace 详情或 token 信息。
- 普通问答有准备上下文、理解需求、整理回复、收尾等兜底阶段；推荐、routine、plan、patch / regenerate 路径会根据工具链进入动作库查询、读取已有训练内容、生成训练安排、校验训练内容和保存训练结果等阶段。
- 已通过 `npm test -- tests/chat-service.test.ts tests/chat-agent-activity.test.ts`、`npm run typecheck` 和 `openspec validate add-agent-activity-indicator --strict`。
