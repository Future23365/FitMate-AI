# Agent 动作刷新重复成功收口

时间：2026-06-04 01:21:16 +0800

## 当前真实问题

生产文本聊天在“换一个”场景中已经能从 `run.metadata.recentExerciseRecommendationFacts` 读取真实 `factRef`，但模型在第 1 轮成功调用 `readRecentExerciseRecommendationFact` 后，第 2、3 轮继续重复同参读取同一个 fact。旧实现会再次执行 handler 并重复登记同一个 consumable resource，最终触发 `Resource id is already registered in the current run.`，以 `invalid_action` hard failure 和空内容错误响应收口。

相邻问题是模型可见 observation 过重：成功 read/import 会把完整 `displayedExercises`、完整 `query` 和 `maxReturned` 等 output-only 字段回灌给模型；`searchExerciseResources` 的模型 observation 也把 `maxReturned` 放在顶层，容易被模型复制成下一轮非法 input。

## 调整思路

本次不让服务端根据“换一个 / 换一批”关键词判断用户语义，也不把具体业务 `toolName` 写进 agent-core 分支。修复分成两层：

1. 业务 tool 的模型可见合同只表达能力边界和状态迁移：成功 read/import 后，该 fact 已导入当前 run，不要重复读取同一 fact；需要新动作时使用 `displayedExerciseIds` 作为 `searchExerciseResources.excludeExerciseIds`。
2. agent-core 增加通用重复成功同参 feedback：同一 run 中若已有相同 `toolName + toolVersion + normalizedInputHash` 且 `ok=true && fulfillment.satisfied=true` 的结果，再次请求相同调用时不执行 handler、不登记 resource，只把结构化 feedback 反馈给 Planner。

## 关键改动

- `readRecentExerciseRecommendationFact` 的 manifest 改为“由 Planner 判断是否需要复用历史 fact”，并移除“用户说某类刷新话术就调用”的表达。
- `readRecentExerciseRecommendationFact.toModelObservation` 改为安全摘要，只保留 `factRef`、`messageId`、`displayedExerciseIds`、必要筛选摘要和“已导入当前 run，不要重复 read”的说明。
- `searchExerciseResources.toModelObservation` 移除 `maxReturned`，保留 `totalMatches`、`returnedCount`、`truncated`、`excludedCount`、`appliedFilters` 和动作摘要，并明确这些统计字段不是 input。
- `runAgentRuntime` 在通用重复调用窄口新增 `duplicate_tool_success` feedback，复用已有成功 `toolResultId`，不消耗真实 tool call，不再次登记 resource。
- 回归测试覆盖 read/import 状态迁移、output-only 字段不污染 input、重复成功同参 feedback、changed input 不误拦截、`satisfied=false` 不被当作成功收口，以及生产聊天“换一个”重复 read 链路。
