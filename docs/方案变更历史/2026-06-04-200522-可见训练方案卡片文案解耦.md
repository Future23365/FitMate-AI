# 可见训练方案卡片文案解耦

记录时间：2026-06-04 20:05:22 CST

## 当前真实问题

`visibleTrainingProposal` 富卡片接入后，聊天正文和卡片摘要出现相同文案。根因不是模型重复输出，而是前端 `ChatPage` 把清理后的 `assistant` 正文传给 `adaptVisibleTrainingProposalToRichCard`，adapter 再把这段正文写入旧卡片 schema 的 `goal` / `summary` 字段。结果是同一个自然语言回答同时出现在 Markdown 正文和富卡片头部，破坏了“正文负责解释、卡片负责结构化训练结果”的展示边界。

## 调整思路

富卡片 adapter 只消费 `visibleOutputs` 里的结构化训练事实，不再读取或派生 `message.content`。正文仍由聊天气泡独立渲染；卡片文案改为由动作数量、肌群、器械、训练日和休息日等结构化字段生成短摘要。这样 UI 不需要理解模型正文，也不会把自然语言回答当作卡片事实。

## 关键改动

- `ChatPage` 渲染 `visibleOutputs` 时不再传入 `assistantContent`。
- `adaptVisibleTrainingProposalToRichCard` 删除正文参数，`exercise_selection`、`routine`、`plan` 分别从结构化 payload/content 生成 `goal` 和 `summary`。
- 推荐动作卡片摘要根据展示动作数量、主要肌群和器械需求生成；单次编排和周期计划摘要根据动作数、预估时长、训练日和休息日数量生成。
- 更新 adapter 和聊天页渲染测试，覆盖卡片摘要来自结构化事实，而不是正文复制。
