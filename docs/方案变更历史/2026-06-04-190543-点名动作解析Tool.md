# 2026-06-04 19:05:43 CST 点名动作解析 Tool 与 requiredExerciseIds 查询合同

## 当前真实问题

trace 显示用户请求“包含俯卧撑、深蹲和平板支撑”时，生产 Agent 只调用了 `searchExerciseResources(q: "俯卧撑")`。另外两个点名动作没有进入数据库事实链路，最终模型只能基于单个查询结果收口。

这个问题不能通过服务端读取用户原文、关键词拆词或 `/api/chat` 语义分流修复。语义识别仍由模型负责，服务端只接收结构化 tool input 并校验数据库事实。

## 调整思路

新增只读业务 tool `resolveExerciseResourceMentions`，稳定 resource 是 `Exercise`，能力族是 `resolve/query`。模型在多点名场景先把用户点名动作结构化为 `mentions`，tool 按输入顺序返回 `matched`、`ambiguous` 或 `not_found`。

扩展现有 `searchExerciseResources.requiredExerciseIds`，把已经解析出的发布态动作 id 作为查询 filter / inclusion hint，优先纳入现有 `groups.<section>.exercises` 列表。输出主结构保持不变，不新增 `requiredMatches`、`supplementalMatches` 或其他并行动作列表。

## 关键改动

- 新增 `lib/server/agent-tools/exercises/resolve-exercise-resource-mentions.tool.ts`，提供中文模型可见说明、严格 schema、只读 policy、projection 和 tests。
- 扩展 `lib/server/exercises/exercise-repository.ts`，新增 mention 解析和按 id 批量读取安全动作摘要的只读入口。
- 扩展 `searchExerciseResources` input schema、handler、diagnostics、projection 和 manifest examples，支持 `requiredExerciseIds`。
- 注册新 tool 到 production `ToolRegistry`，不改 orchestrator main loop、`PlannerPort`、Executor、Policy Guard、Resource Contract Validator、Response Renderer 或 `/api/chat`。
- 新增/更新 tool-level、manifest、contract helper 和生产聊天 replay tests，覆盖“俯卧撑、深蹲、平板支撑”两步 tool 链路。
