# 聊天黑盒流程回归修复

## 真实问题

`docs/manual-llm-blackbox-flow-latest-report.md` 显示首页聊天黑盒流程在核心链路调整后出现 6 个失败和 8 个级联跳过。失败不是动作库或前端展示问题，而是聊天意图边界在真实模型输出中不稳定：

- “今天我想练胸”“那我今天练胸”这类目标明确的纯推荐，被模型追问器械或时长，没有推送 `exercise_recommendation`。
- “改成45分钟”没有稳定继承最近 routine，反而进入历史 artifact 语义检索并要求用户确认对象。
- “我有哑铃”只是条件事实，却被模型补默认目标和时长后误触发 `workout_routine`。
- “给我一个6天训练计划”已表达长期计划语义，但又被缺少器械或经验阻断。

## 调整思路

模型仍负责自然语言理解，但黑盒主路径中的稳定短语不能只靠 prompt 约束。服务端在意图解析后增加一层归一化：把目标明确的纯推荐、孤立条件事实、短指令调整和长期计划短语收敛成确定性边界，再让候选筛选和内部动作触发使用归一化后的结果。

这保留了 `conversationSummary + latestUserMessage` 的上下文边界，没有回退到完整历史消息窗口；短指令所需的最近训练事实来自服务端内部 `conversationContext.currentIntent` 和 recent artifact 摘要。

## 关键改动

- 新增 `fix-chat-blackbox-flow-regressions` OpenSpec change，记录黑盒失败的修复范围、设计和验收任务。
- 在 `chat-service.ts` 中增加 `normalizeChatIntentForBlackboxFlows()`，修复纯目标推荐、孤立条件输入、短指令继承和长期计划触发。
- 对“改成45分钟”这类无显式引用标记的当前 routine 调整跳过 ReferenceResolver，避免进入语义检索歧义分支。
- 收紧 `chatIntentResolution` prompt，明确“今天想练胸”仍是纯动作推荐，“我有哑铃”只是条件事实，“6 天训练计划”必须保持 plan 语义。
- 增加单元测试覆盖报告中的关键失败样例。
