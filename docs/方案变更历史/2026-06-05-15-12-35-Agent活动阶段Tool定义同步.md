# Agent 活动阶段 Tool 定义同步

时间：2026-06-05 15:12:35 CST

## 当前问题

聊天活动条的中文文案由前端 `agentActivityDisplayByStage` 白名单维护，这是合理的用户安全边界。但生产聊天接入层此前还维护了一个具体 `toolName -> AgentProgressStage` 映射。新增或重命名生产 tool 时，如果忘记同步这张表，用户看到的活动阶段就会和真实 tool 执行不同步。

更隐蔽的问题是，直接把 `uiActivityStage` 放入 `Tool.metadata` 虽然能靠近 tool 定义，但 `metadata` 会进入 Planner manifest，等于把 UI 展示字段暴露给模型。

## 调整思路

本次把活动阶段声明收敛到 tool definition 的服务端内部字段 `uiActivityStage`：

- tool 自己声明适合展示的粗粒度 `AgentProgressStage`。
- production chat adapter 只读取 `tool.uiActivityStage`、稳定 resource contract fallback 或通用 `analyzing_request`。
- 前端继续只维护 `stage -> 中文文案` 白名单。
- `uiActivityStage` 不进入 Planner manifest，不改变模型可见合同。

## 关键改动

- `searchExerciseResources`、`resolveExerciseResourceMentions` 声明为 `querying_exercises`。
- `inspectVisibleTrainingProposals` 声明为 `reading_artifacts`。
- 删除 `agent-text-chat-service.ts` 中具体业务 `toolName` 活动阶段表。
- 增加测试，证明生产 tool 活动阶段在 tool definition 上，且不会出现在 Planner manifest。
- 增加 architecture boundary，防止 chat service 重新维护具体 toolName stage map。

## 结果

后续新增需要具体活动提示的生产 tool 时，应该在 tool definition 中声明 `uiActivityStage`，而不是修改 chat service 的集中映射表。这样活动条展示、tool 能力和注册定义同源，同时不扩大模型可见输入。
