# Agent 文本聊天生产接入

时间：2026-06-03 16:41:50 CST

## 原问题

旧运行时 AI/Agent 删除后，`/api/chat` 只返回 `chat_ai_disabled`。这让首页聊天能保留历史展示，但无法验证新 `agent-core`、`LlmPlanner`、DeepSeek adapter 和默认 Response Renderer 的真实用户闭环。

## 调整思路

本次不接入任何业务 tool，先恢复最小真实文本聊天能力：服务端把已校验请求和 hydration 结果转换为 `AgentRunInput`，生产路径使用空 `ToolRegistry`，由 `LlmPlanner + DeepSeekModelAdapter` 产出 `AgentAction` candidate，再交给 `runAgentRuntime()` 校验和收口。前端只消费 `content`、`assistant_suggestions`、`error`、`done` 等通用 NDJSON 事件。

## 关键改动

- 新增 `lib/server/chat/agent-text-chat-service.ts`，集中处理 production `/api/chat` 到 `agent-core` 的薄适配、DeepSeek planner factory、空 registry 和 NDJSON 响应。
- `app/api/chat/route.ts` 从禁用响应切换到文本聊天 NDJSON 响应。
- `features/chat/api/chat-client.ts` 改为 NDJSON stream client，覆盖跨 chunk、空行、非法 JSON、HTTP 错误和 abort。
- `features/chat/hooks/use-chat-controller.ts` 只把通用事件投影到当前 assistant message，不根据用户文本推断训练卡片、动作推荐或保存结果。
- 后端、前端和架构扫描测试证明本阶段没有旧 `agent-orchestrator`、旧事件、fixture tool 或真实业务 tool 回流。

## 结果

生产 `/api/chat` 已能通过新 `agent-core` 返回文本回答、澄清问题、建议回复和稳定错误。缺少 `DEEPSEEK_API_KEY` 时返回 `chat_ai_not_configured`，不再把缺配置伪装成旧 AI 下线。当前仍不支持动作检索、训练生成、artifact 保存或用户记忆，这些能力必须由后续独立 business tool change 接入。
