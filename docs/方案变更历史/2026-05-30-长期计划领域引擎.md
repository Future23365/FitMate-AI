# 2026-05-30 长期计划领域引擎

## 当前问题

长期训练计划如果直接让 LLM 铺满完整日历，训练日数量、休息日、周频率、递进和连续负荷很难稳定校验。用户说“三周都练这个”“改成一周四练但别太累”时，系统更需要复用已确认的 routine / plan artifact，并由服务端规则展开计划预览。

## 调整思路

把长期计划拆成两层：聊天与 LLM 只负责理解意图、解析引用并生成 `PlanStrategy`；`DomainPlanEngine` 根据 strategy 和受控 artifact payload 展开训练日、休息日、递进策略和 `schedulePreview`。这样可以把频率、周期和恢复边界放进可测试的 TypeScript 代码。

## 怎么做的

- 新增 `PlanStrategy` schema，明确 `horizonDays`、`weeklyFrequency`、`sessionMinutes`、`strategy`、`progressionPolicy` 和 `intensityBias`。
- 新增 `DomainPlanEngine`，支持重复 routine、保守递进、weekly split 和 AB 交替的基础展开。
- `/api/chat` 继续输出 `referenceResolution`，前端把引用传给 `/api/ai/workout-plan`，由服务端读取完整 artifact payload。
- Validator 补充长期周期、周频率和连续高负荷校验，避免未通过规则的计划进入卡片或保存流程。

## 结果

“三周都练这个，一周三练”会生成 21 天、9 个训练日的 schedule preview；“改成一周四练但别太累”会按保守强度展开，不再让 LLM 自由生成不可复盘的长期日历。
