# 聊天 Artifact 查看与建议边界收紧

时间：2026-06-02 21:27:31 CST

## 当前真实问题

最新聊天 trace 暴露出同一类边界问题：短回复可能被带入执行型失败出口；查看刚才生成的训练时 Agent 能读到 artifact 摘要或 payload，但聊天流没有重新推送 routine / plan 卡片；用户可见建议里会出现当前产品未开放的保存或验证后保存动作；同一 assistant 气泡和同一 payload 可能经 Agent 写入与聊天自动保存两条入口产生重复 active artifact；`buildFitnessConversationContext()` 还会把操作性 raw text 误提取为 `knownFacts.goal`。

这些问题不能靠前端隐藏或关键词拦截解决，否则会重新引入服务端自然语言语义判断，并继续污染 Agent 上下文事实源。

## 调整思路

本次调整把边界收紧在确定性合同层：

- Agent prompt 明确普通回答、澄清、只读 artifact 查看、训练生成、训练修改和写入成功的终止条件。
- `assistantSuggestions` 增加结构化 `targetOperation`，Response Writer 按产品能力过滤未开放写操作建议，不读取 label/message 文案关键词。
- artifact 查看只从本轮成功 `getArtifactPayload` tool result 的完整 payload 投影聊天卡片，不从回复正文、summary 或 recent artifact summary 反建 payload。
- `responseMessageId` 由 Agent runtime context 注入写工具，模型输入中的同名字段只保留兼容诊断价值。
- artifact service 按同 message、稳定 payload 和未绑定旧 artifact 收敛 active 记录，并在 recent summaries 返回前去重。
- 上下文摘要删除 raw text 宽泛 goal 提取，仅保留时长、周频、器械等低歧义事实。

## 关键改动

- `lib/server/agent-orchestrator/response-writer.ts`：实现结构化 suggestion capability gate，并在 projection metadata 记录被过滤建议。
- `lib/server/chat/chat-service.ts`：支持 `answered + getArtifactPayload` 的 routine / plan 只读卡片重投影，并在 trace / done metadata 中标记 `read_only_artifact_payload`。
- `lib/server/agent-orchestrator/runtime.ts` 与 `workout-tools.ts`：把服务端 `responseMessageId` 注入 tool context，保存 artifact 时优先使用 context 绑定。
- `lib/server/conversation-artifacts/artifact-service.ts`：稳定 payload 比较、旧未绑定 artifact 收敛、recent active index 去重。
- `lib/shared/chat/fitness-conversation-context.ts`：移除 raw user message 的高层 goal 提取。
- `manual-tests/llm/flow-fixtures.ts`：新增短确认、短否定、查看刚才训练和模拟点击建议生成训练的黑盒 flow。
