# LangChain 单 Tool 重复请求过滤

时间：2026-06-11 19:15:21 CST

## 背景

上一轮预算重平衡把整轮业务 tool 总预算调为 20，并为每个业务 tool 增加 `maxToolCallsPerTool = 2`。实现使用 LangChain 原生 `toolCallLimitMiddleware({ runLimit: 2, exitBehavior: "continue" })`。

真实 trace 暴露出一个语义缺口：`exitBehavior = "continue"` 只会在超限时阻止 handler 执行，并把失败 ToolMessage 返回给模型；如果模型持续不收口，它仍然可以在后续 provider model call 中继续请求同一个 tool，直到耗尽 `maxModelCalls` 或整轮总预算。

这会造成用户看到“同一个 tool 重复调了 20 次”的现象。严格拆开看，handler 实际只执行了 2 次，但 provider `tool_calls` 确实重复尝试到了总预算附近。这不符合“单个 tool 最多重复一次修正”的产品语义。

## 调整思路

本次把 per-tool 限制拆成两层：

- 请求前过滤：每次 provider model call 前，runtime 统计当前 run 中已经出现过的业务 provider `tool_calls`；达到 `maxToolCallsPerTool` 的业务 tool 会从后续 `request.tools` 中移除。
- 执行兜底：继续保留 LangChain 原生 `toolCallLimitMiddleware`，处理同一 provider response 内一次性返回多个同名 tool_calls 的场景，确保超限调用不执行 handler。

两层逻辑都基于 production tool wrappers 自动生成，不读取用户原文，不写关键词、短句模板或具体业务 phrasing 分支。

## 关键改动

- 在 LangChain runtime 新增 `FitMateBusinessToolAvailabilityMiddleware`。
- 该 middleware 在 `wrapModelCall` 中按当前 run 的历史 `AIMessage.tool_calls` 计数。
- 当某个业务 tool 达到 `maxToolCallsPerTool` 后，后续 model request 不再暴露该 tool。
- `reportAgentActivity` 不参与业务 per-tool 过滤，仍使用独立 activity 预算。
- 新增连续多轮重复调用同一业务 tool 的回归测试，断言 provider `tool_calls` 不会继续增长到总预算 20。

## 结果

修复后，同一个业务 tool 在一次 run 中达到 2 次 provider tool_call 后，会从后续请求的可用工具中消失。模型仍可使用其他未达上限的业务 tool，也可以直接收口或澄清；但不能继续把同一个 tool 重复请求到 20 次。

验证命令：

```bash
npm test -- tests/langchain-agent-runtime/runtime.test.ts
```
