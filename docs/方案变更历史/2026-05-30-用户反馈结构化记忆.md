# 2026-05-30 用户反馈结构化记忆

## 当前问题

用户在聊天和训练中会持续表达偏好和反馈，例如“不喜欢俯卧撑”“平板支撑太难”“今天不想练腿”“肩膀不舒服”。如果只把这些内容写进 `conversationSummary`，候选动作、Patch 和长期计划生成无法稳定复用；如果不区分长期和临时，又容易把“今天不想练腿”沉淀成永久画像。

## 调整思路

把用户反馈从自然语言摘要升级为服务端结构化记忆。长期偏好、动作级反馈、临时上下文、健康/不适信号和训练完成行为分层保存，并在读取时固定优先级：当前消息优先于当前 artifact、显式画像、近期反馈、训练结果和系统默认值。

## 怎么做的

- 新增 `UserMemory` 和 `UserExerciseFeedback` 持久化结构，保存 kind、subject、value、confidence、source、expiresAt、requiresConfirmation 和 status。
- 新增 `UserFeedbackMemoryService`，负责识别聊天反馈、写入记忆、构建 Conversation Memory State，并给 prompt、候选检索和计划服务提供统一读取入口。
- 动作候选服务读取 active 记忆：长期 dislike 会排除或降权动作，too_hard 会影响降阶替代排序，临时上下文会在过期前参与过滤。
- 训练完成结果的 `feedback` 保存完成率、跳过动作、实际时长和主观疲劳；DomainPlanEngine 会根据低完成率或高疲劳走保守递进。
- 长期强约束和健康/不适信号默认标记 `pending_confirmation`，确认前不会作为已生效长期排除规则。

## 结果

聊天中的显式反馈可以被后续推荐、Patch 和长期计划复用；临时反馈有过期时间，不污染长期用户画像；动作和训练结果读取都基于 `userId` 隔离，避免跨用户记忆污染。
