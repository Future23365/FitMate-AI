# 2026-06-05 13:46:49 CST 可见训练资源消费合同收紧

## 问题

`visibleTrainingProposal`、`inspectVisibleTrainingProposals(read_recent)` 和 `searchExerciseResources` 已经能各自提供可见训练事实，但模型在组合这些事实时缺少统一的消费语义。上一轮已展示动作有时应作为正向来源，有时才应作为负向排除；只覆盖 `training` 的事实也可能被误当成完整 `routine` / `plan` 的依据，导致缺少 `warmup` / `stretch` 时仍尝试输出完整结构。

如果用服务端短句判断或固定 tool 流程修复，会重新把自然语言语义放回服务端，违背 Agent 边界。

## 调整思路

把问题收敛为模型可见的资源消费合同：

- 通用 prompt 增加 `reuse`、`derive`、`modify`、`replace`、`clarify` 推理标签，只作为模型理解资源操作的分类，不进入服务端 action schema。
- `read_recent` observation 和 consumable resource summary 明确 `availableSections`、`missingSectionsForRoutineOrPlan`、`supportsOutputKinds`、正向消费和负向排除边界。
- `searchExerciseResources` 把 `requiredExerciseIds` 明确为正向锚点，把 `excludeExerciseIds` 明确为替换、排除或避免重复时的负向约束，并让 observation 只把实际返回动作的 section 视为可消费 coverage。
- `visibleTrainingProposal` validator 在缺 section 或 section 不合法时返回结构化 repair 诊断，包含 code、path、coverage、缺口和可恢复方向。

## 关键改动

- 新增业务层 coverage helper，统一计算 `warmup` / `training` / `stretch` 覆盖和 output support。
- 升级默认 Agent prompt 到 `agent-action-v9`。
- 增强 `inspectVisibleTrainingProposals` 与 `searchExerciseResources` 的模型可见说明和 observation。
- 增强终态 `visibleTrainingProposal` 校验失败 details，供下一轮 Planner repair。
- 补充 prompt、manifest、tool observation、validator、production replay 和架构边界测试。
