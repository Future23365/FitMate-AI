# 数据库时间格式标准化

时间：2026-05-31 22:16:57 CST

## 背景问题

项目之前同时存在 PostgreSQL `TIMESTAMP(3)`、服务端本地时间格式化、测试 fixture 中无 offset 时间字符串等写法。聊天历史排序、训练日历归属、训练执行时长、用户记忆过期和 AI trace 时间线都依赖这些值，一旦运行环境或数据库 session 时区不同，就可能把同一个业务事实解释成不同时间点。

## 调整思路

这次不只在输出层补 `toISOString()`，而是把数据库列类型、迁移语义、服务 DTO、输入校验、fixture 和扫描测试一起收口。历史 migration 保留原样；新增 forward migration 明确把旧 timestamp 按 UTC+0 解释后转换为 `TIMESTAMPTZ(3)`。

## 关键改动

- `prisma/schema.prisma` 中所有代表具体时间点的 `DateTime` 字段显式加上 `@db.Timestamptz(3)`。
- 新增 `20260531221657_standardize_database_time_format` migration，使用 `AT TIME ZONE 'UTC'` 转换既有列。
- 新增共享 UTC 时间工具，统一 `Date` 序列化、UTC datetime 输入校验和日期 key 的 UTC 零点派生。
- 聊天历史、训练持久化、artifact 检索、匿名鉴权、confirmation token 和 AI trace 写入路径改为使用 UTC helper。
- 增加自动化扫描测试，防止新增 `DateTime` 缺少 `@db.Timestamptz(3)`、新 migration 引入无时区列或 fixture 继续使用无 offset 时间。

## 结果

数据库事实层和服务端边界现在统一以 UTC-aware 时间点表达；`WorkoutSchedule.scheduledFor` 作为日期型流程仍使用 `DateTime`，但固定写入 UTC 零点，并从 UTC 值派生 `YYYY-MM-DD`。
