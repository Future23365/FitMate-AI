# 训练合理性 Hard Fail 移除

时间：2026-05-31 22:50:35 CST

## 背景

用户明确要求“今天明天后天都练这个”时，长期计划领域引擎已经能基于最近 routine 展开重复训练日，但训练草稿校验层仍会把重复训练日、连续负荷和时长推断不一致当作 hard fail，导致计划卡片无法展示。

这个问题暴露出校验层职责过宽：它同时在判断结构是否可执行，以及训练安排是否足够合理。前者是服务端确定性边界，后者应由 LLM 结合用户语义和候选动作说明承担。

## 调整思路

本次把 `WorkoutPlanValidationResult.errors` 收敛为确定性契约失败，只保留动作 ID、候选集合、必要结构、payload 内部计数和用户明确约束。训练日重复、连续负荷、训练量偏高、休息偏短、新手容量偏高、section 语义分歧和旧偏好冲突统一进入 `warnings`。

时长和周频率不再天然 hard fail。只有字段来源是 `current_user_message`，或 `history` / `artifact` 且调用方显式标记为已确认约束时，`session_too_long`、`session_too_short`、`weekly_frequency_mismatch` 才会进入 `errors`。默认值、LLM 推断值和未确认旧字段只记录 warning。

## 关键改动

- `workout-plan-validation-service.ts` 新增字段来源和已确认约束输入，用它决定时长、频率、避免动作和训练禁忌是否 hard fail。
- `day_similarity_high`、`consecutive_load_high` 和合理性诊断从 errors 降级为 warnings，重复当前 routine 的长期计划可以正常展示。
- `workout-plan-validation-recovery-service.ts` 只根据 `validation.errors` 分类失败和可恢复状态，warning 不再触发自动修复或 `plan_validation_failed`。
- AI 修复 prompt 改为只修复契约失败，不再要求模型修复合理性 warning。
- DomainPlanEngine 生成分支把 `PlanStrategy.fieldSources` 传入校验层，普通 AI 生成分支传入聊天解析出的 `fieldSources`。
