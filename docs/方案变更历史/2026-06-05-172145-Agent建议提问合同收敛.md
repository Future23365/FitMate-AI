# 2026-06-05 17:21:45 CST Agent 建议提问合同收敛

## 背景

聊天主链曾同时存在 `final_answer.assistantSuggestions`、`ask_user.suggestions`、`assistant_suggestions.suggestions`、前端 `suggestedReplies` 和历史 `suggestedQuestions`。这些字段都能表现为按钮，但语义分别像下一步建议、澄清选项、旧事件 payload 或历史兼容字段，导致模型输出、Response Renderer、前端状态和聊天历史之间没有一个稳定主合同。

## 调整思路

本次把用户可见建议统一定义为 `suggestedQuestions?: string[]`：每一项都是建议提问，按钮文字就是点击后发送的下一轮普通用户消息。`final_answer` 和 `ask_user` 都使用同一个可选字段；Response Renderer 只输出 `suggested_questions` 事件；前端 message 和聊天历史只保存 `suggestedQuestions`。

## 关键改动

- `AgentAction` 终态 schema 删除旧主路径字段，新增受控 `suggestedQuestions`，限制最多 3 条、非空、长度受控。
- 默认 Agent prompt 增加 `suggestedQuestions` 通用合同，说明可选性、用户口吻、直接发送、不得重复正文和不得承诺未注册能力。
- `/api/chat` 生产投影和失败 fallback 改为 `suggested_questions`，trace summary 记录最终可见 `suggestedQuestions`。
- 前端 NDJSON parser、controller、message 类型和聊天页面只消费 `suggestedQuestions`，不再用复杂 `AssistantSuggestion` adapter 把旧字段转成按钮。
- 聊天历史新写入和读取只使用 `suggestedQuestions`，不把旧 `suggestedReplies`、`assistantSuggestions` 或 `assistant_suggestions` 迁移成新字段。

## 取舍

本次不迁移旧建议协议，也不保留旧事件兼容转换。这样会让旧历史里的旧按钮不再自动转成新按钮，但换来主链合同清晰：建议提问只是下一轮普通用户消息候选，不能绕过 AgentAction、tool schema、ResourceStore、Policy Guard 或 validator。
