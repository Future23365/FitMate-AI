# 2026-06-04 00:52:03 CST Agent 模型可见描述中文化

## 当前问题

新的 `agent-core` 已经把通用 `AgentAction` system prompt 改成中文，但业务 tool 的 manifest 里仍有英文 `description`、`whenToUse`、`whenNotToUse` 和 example description。这些字段会原样进入 Planner 可见输入，导致模型同时看到中文通用合同和英文业务能力说明。

问题不在 runtime，也不是模型语义理解错误，而是模型可见合同缺少语言规范。只在 `AGENTS.md` 中要求中文回复，无法保证 tool manifest 和 schema description 后续不会继续写成英文。

## 调整思路

本次把规则分三层落地：

1. `AGENTS.md` 记录仓库级原则：模型可见描述性自然语言默认中文。
2. `agent-prompt-contract-governance` 和 `agent-tool-change-governance` 记录执行流程：修改 prompt / model input / tool manifest 时必须检查语言边界。
3. manifest hardening 和 registry manifest 测试记录自动化护栏：描述字段要有中文说明，结构化标识保持英文原样。

## 关键改动

- 新增 `localize-agent-model-visible-descriptions` OpenSpec change，定义本次模型可见描述语言合同。
- 补充 `AGENTS.md`、两个治理 Skill 和 `docs/agent-tool-orchestrator-design.md`。
- 将当前生产 tool 和 fixture tool 的模型可见英文说明改为中文。
- 在 manifest hardening 中增加描述字段中文检查，避免后续英文说明重新进入 Planner manifest。

## 取舍

本次不做运行时翻译，也不禁止所有英文字母。`toolName`、字段名、enum、action type、resource type、schema id、错误码、路径和代码标识符仍保持英文，因为它们是执行合同的一部分。自动化测试只检查描述性字段包含中文，完整语义仍由人工 review 和 OpenSpec 边界保证。
