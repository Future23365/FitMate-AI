# Agent 活动条接入新核心链路

时间：2026-06-04 22:04:34 +0800

## 原方案为什么不合适

旧 `AgentActivityIndicator` 随旧 Agent runtime 删除后，首页聊天只剩泛化的“正在思考”。这让用户在新 `agent-core` 文本聊天链路执行 tool 查询、校验和整理回复时看不到推进状态。

直接恢复旧 `agent_activity` 事件不合适，因为旧事件属于已删除的 `AgentOrchestrator` stream 合同，容易把旧 `assistant_action`、训练卡片触发和兼容 reducer 一起带回生产链路。

## 调整思路

本次只恢复活动条体验，不恢复旧运行时合同。新链路使用 `agent_progress` 作为当前请求级临时 UI 事件：

- `agent-core` 只增加非致命、只读的 `onTraceEvent` 观察点。
- `agent-text-chat-service` 负责把已发生的 runtime 生命周期投影为用户安全阶段。
- 最终 `content`、`visible_output`、`tool_result`、`confirmation_request`、`assistant_suggestions`、`error` 和 `done` 仍由 Response Renderer 或现有安全边界输出。
- 前端只把 `agent_progress` 保存在当前请求 state 中，不写入 `ChatMessage`、聊天历史、conversation summary、conversation context 或 artifact payload。

## 关键改动

- 新增 `AgentProgressEvent` / `AgentProgressStage` 合同，事件名为 `agent_progress`。
- `runAgentRuntime()` 的 trace 写入统一经过只读观察 helper，观察失败会被吞掉，不影响 Planner、Validator、Executor、Policy Guard、ResourceStore 或 terminal action。
- `/api/chat` 文本聊天响应改为 streaming writer，可在 runtime 执行过程中先输出 `agent_progress`，再输出最终 renderer 事件。
- 前端 `chat-client` 增加 `agent_progress` payload 校验；未知 stage 只进入安全兜底文案，非法 status / sequence / messageKey 直接按 stream 错误处理。
- 重建 `AgentActivityIndicator` 和 `features/chat/lib/agent-activity.ts`，复用旧紧凑行内视觉与展示仲裁规则，但只接受新 `agent_progress`。
- `ChatPage` 将活动条放在当前 assistant 气泡顶部，`ChatThinkingIndicator` 保持在活动条下方。

## 怎么做的

实现边界按生产接入层拆开：

- core：只暴露通用 runtime event observer。
- adapter：把 `AgentTraceEvent` 映射成安全 UI 阶段，payload 不包含 prompt、raw model output、toolName、tool input / output、resource id、token usage、权限信息、数据库 payload、trace JSON 或错误栈。
- frontend：请求开始设置临时兜底状态；收到 `agent_progress` 后按 sequence 和具体阶段优先级仲裁；收到 `content` 可切到 `writing_reply`；收到 `done` / `error` / abort / timeout / 会话切换 / 新建会话后立即清理。
