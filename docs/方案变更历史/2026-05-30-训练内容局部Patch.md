# 训练内容局部 Patch

## 当前问题

用户在聊天里说“把俯卧撑换掉”“平板支撑太难，换简单点”时，真实需求通常是只改当前训练卡片中的一个动作或一个执行参数。旧链路更容易走整份训练重生成，结果会误改未点名的动作、训练日、循环配置或休息配置，也无法在调试链路里说明到底改了什么。

## 调整思路

这次把训练内容修改从“重新生成整份草稿”改成受控 `WorkoutPatch`。Patch 必须带上 artifact、section、exerciseId 和必要的 occurrenceIndex；第一版只允许 `artifact_only`，不直接覆盖 saved routine、future schedule 或 completed history。替代动作必须来自服务端候选集合，并经过动作存在性、阶段、器械、难度和风险边界校验。

## 怎么做的

- 新增 `WorkoutPatch` / `PlanPatch` schema，明确 scope、locator、operation、preserve 和 result。
- 新增 PatchEngine：读取目标 `ConversationArtifact` payload，应用 `replace_exercise`、`adjust_load` 和安全 `remove_exercise`，输出 diff，并通过 artifact service 创建新 revision。
- 聊天链路在 ReferenceResolver resolved 且用户表达为局部修改时，走确定性 Patch 分支；成功后推送新的训练卡片 payload，失败时返回澄清或可继续对话的引导。
- 非 `artifact_only` scope 统一返回 blocked，避免误改已保存训练、未来日程或历史记录。

## 当前结果

局部替换会保留未点名动作、训练日、组数、目标次数/时长和休息参数，并在结果 diff 中记录原动作、替代动作、保留字段和失败原因。已补充单元测试覆盖单动作替换、重复动作歧义、候选外动作拒绝、completed history blocked、单目标降负荷和聊天 Patch 编排。
