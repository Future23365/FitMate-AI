# RAG 混合检索

## 当前问题

结构化字段能保证权限和训练规则，但用户会用“拜拜肉”“核心不稳”“圆肩”“之前那个练胸的”等模糊表达。旧链路主要依赖 prompt、recent summaries 和简单文本匹配，容易召回不足；如果直接把向量结果交给模型，又会增加越权和动作规则绕过风险。

## 调整思路

这次把 RAG 定位为受控检索层，而不是规则引擎。artifact 和 exercise 都生成安全的 `embeddingText` 与固定维度 embedding；查询时先执行 userId、status、kind、section、器械、难度、风险等硬过滤，再在过滤后的候选集合内做全文匹配、向量相似度和业务 rerank。

## 怎么做

- `ArtifactIndex` 与 `Exercise` 增加 `embeddingText` / `embedding` 字段，第一阶段使用 PostgreSQL `Json` 保存本地 hashing embedding。
- `searchArtifacts` 升级为 hybrid search，并在 `ReferenceResolver` 中记录 `rag_query` trace。
- `searchExercises` 支持模糊动作表达，动作候选服务把 hybrid recall 作为排序加权，最终仍由分池和 Validator 约束。
- 新增 `npm run db:refresh-embeddings`，用于迁移后刷新既有动作和 artifact 索引。

## 结果

模糊表达可以在不暴露完整 payload、不绕过权限和训练硬约束的前提下进入候选排序；trace 中能看到 query、过滤条件、召回数量、rerank 理由和最终候选 id。
