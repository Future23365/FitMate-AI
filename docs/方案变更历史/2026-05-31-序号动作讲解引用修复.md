# 序号动作讲解引用修复

## 真实问题

最新 `docs/manual-llm-blackbox-flow-latest-report.md` 中 `F15` 第 3 轮失败：用户已经先生成胸部动作推荐，并把它升级成 20 分钟 routine 后，再问“第一个动作怎么做”。系统本应解释最近 routine 或推荐里的第一个动作，但实际又触发了一批新的 `exercise_recommendation`。

这个问题不是动作库缺数据，而是聊天语义边界不完整：`第一个动作怎么做` 没有被稳定归一为动作讲解，也没有稳定解析到最近 artifact 的第 N 个动作。

## 调整思路

服务端把序号动作讲解收敛成确定性链路：

- `第一个动作怎么做` 这类短句归一为 `exercise_explanation`，并禁止触发训练卡片。
- ReferenceResolver 把“第 N 个动作”当成最近 artifact 引用，优先命中当前会话最新 active artifact。
- 解析成功后读取 artifact payload，按展示顺序取第 N 个 `exerciseId`。
- 再通过动作库按 `exerciseId` 读取动作详情，生成确定性讲解回复。

这个方案保留 LLM 的自然语言理解职责，但不把任意数据库查询能力暴露给 LLM。

## 关键改动

- `lib/server/chat/chat-service.ts` 增加序号动作讲解归一化、artifact payload 顺序取动作和确定性讲解回复。
- `lib/server/reference-resolver/reference-resolver-service.ts` 增加序号引用识别，让“第一个动作”命中最近 artifact。
- `tests/chat-service.test.ts` 和 `tests/reference-resolver-service.test.ts` 增加 F15 第 3 轮的确定性回归。
- `openspec/changes/fix-blackbox-chat-flow-regressions` 补充本次 F15 范围、设计和任务。
