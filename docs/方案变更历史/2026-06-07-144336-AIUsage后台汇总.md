# 2026-06-07 14:43:36 AI Usage 后台汇总

## 当前问题

生产聊天链路已经能在 AI trace 中展示模型 token usage，但 trace 是诊断层：生产可以关闭、截断、清理或导出到 `codex_logs`，不能作为正式后台统计来源。聊天消息正文和 `ChatMessage.metadata` 也不适合作为 token 统计表，否则聊天历史重写会影响统计事实。

## 调整思路

本次把生产 token usage 从 Trace 中解耦，新增独立 `AiTokenUsageSummary` 表作为后台统计事实源。聊天请求内的 planner、repair 和 terminal failure finalizer 多次模型调用只汇总为同一请求 / assistant 消息级 token 数量，不保存 Agent loop、planner call、model call、source、错误日志或内部执行轨迹。

后台访问通过集中配置 `FITMATE_ADMIN_USER_IDS` 和统一 admin guard 控制。后台页面和后台数据 route 只消费 `admin-ai-usage-service` 的投影对象，不直接依赖 Prisma include shape、usage 原始表结构、Trace shape 或导出日志。

## 关键改动

- 新增 `AiTokenUsageSummary` Prisma model 和迁移，字段包含 `userId`、`conversationId`、`messageId`、输入 token、输出 token、总 token、未知 usage 标记和时间字段。
- 新增 `lib/server/usage/ai-token-usage-summary-service.ts`，负责生产 token 汇总、partial/no usage 边界、幂等 upsert 和写入失败隔离。
- 在 `/api/chat` 生产链路中读取已归一化 `ModelTokenUsage`，合并 planner、repair 和 finalizer usage 后写入 summary。
- 新增 `lib/server/config/admin-config.ts` 和 `lib/server/auth/admin-guard.ts`，集中解析管理员 userId，并统一处理 401 / 403。
- 新增 `lib/server/admin/admin-ai-usage-service.ts`、`/api/admin/ai-usage` 和 `/admin` 页面，提供全站、用户、会话、消息级只读投影。
- 更新 README、数据库设计说明和 OpenSpec tasks，明确后台统计不读取 Trace、`codex_logs` 或 `ChatMessage.metadata`。

## 结果

后台 token 统计现在有独立生产表和服务投影。Trace 继续保留诊断 usage 摘要，但不再承担生产统计职责。partial usage 和 provider 未返回 usage 会显示为未知，不会被误读为真实 0。
