# 训练校验确定性边界

最新训练生成链路里，用户说“30分钟，练这个”时，候选动作和 routine 意图已经成立，但服务端把 `Knee_Circles`、`Wrist_Circles` 放入 `warmup` 视为 `section_exercise_mismatch` 硬失败。问题不在动作 ID、候选集合或安全边界，而是服务端用静态 `allowedSections` 覆盖了 LLM 对动态热身语义的判断。

这次把训练草稿校验边界收敛为“确定性事实优先”：不存在的动作、候选外动作、Schema 无效、缺少必要结构、用户限制、时长和训练量异常继续阻止草稿展示；动作 section 与本地元数据不一致只记录 warning，进入 AI Trace 诊断，不再触发 `plan_validation_failed` 或要求用户补目标、器械、时长。

关键改动：

- `section_exercise_mismatch` 从 validation `errors` 降级到 `warnings`，warning 保留 `exerciseId`、AI section 和本地 `metadataSections`。
- 自动恢复分类只把确定性边界作为 hard boundary，修复 prompt 继续只处理结构、候选、时长和训练量问题。
- AI Trace 的 validation metadata 增加 `deterministicHardFailCodes` 与 `sectionSemanticWarnings`，排查时可区分真正阻断和语义诊断。
- 候选分池仍用于 prompt 提示和排序，但总候选集合保留合法动作，避免 `allowedSections` 过窄阻止模型使用。

这让服务端继续承担事实、安全和可执行性校验，同时避免用粗粒度动作元数据误杀合理的训练编排。
