# 动作推荐追问门控

## 调整原因

最新 AI trace 中，意图解析已经返回 `canTriggerAction = false`、`missingActionFields` 和 `suggestedReplies`，但服务端仍因为 `exercise_recommendation` 的目标字段非空触发了动作推荐。这导致“建议用户补信息”和“已经推送动作”同时出现，用户看到的行为和意图判断不一致。

## 调整结果

聊天触发门控现在把 `exercise_recommendation` 的建议追问视为更高优先级信号：当 `canTriggerAction = false` 且 `suggestedReplies` 非空时，服务端不会触发动作推荐，而是保留建议回复给用户点击补充。

同时保留“目标明确即可推荐动作”的产品规则：模型按提示返回 `canTriggerAction = true` 且没有建议追问时，服务端仍会在候选动作可用时直接推送 `exercise_recommendation`。

## 解决的问题

- 避免意图解析已经建议追问时，服务端仍推送动作。
- 避免 `suggestedReplies` 被内部动作触发静默隐藏，造成 trace 和界面状态难以解释。
- 避免把 Schema 默认值和未确认条件当作已满足的动作推荐条件。
- 保留“我想练腿”这类纯动作推荐的低门槛体验。
