# 聊天黑盒流程二次回归修复

## 真实问题

最新 `docs/manual-llm-blackbox-flow-latest-report.md` 在上一轮修复后仍剩 3 个失败：

- 已有胸部动作推荐后，用户说“推荐几个不用器械的”，系统误触发 `workout_routine`。
- 用户只说“给我一个每周训练计划”时，系统用默认目标、默认时长和默认频率直接生成了空泛 `workout_plan`。
- 用户上一轮只记录“我有哑铃”后，下一轮“今天练胸30分钟”没有继承哑铃条件，反而继续追问器械。

这些问题说明第一版归一化只覆盖了首轮基础语义，还没有把“推荐细化”“空泛 plan 补齐”和“durable facts 继承”拆成稳定边界。

## 调整思路

继续把服务端归一化作为最终边界，而不是只加强 prompt。归一化层新增三类判断：

- 最近是动作推荐时，仍含“推荐、动作、几个、换一批”等语义的短句只视为推荐细化。
- 长期计划只有类型意图、缺少目标和核心条件时，不允许默认补齐后推送计划。
- 器械、场地、时长、频率等 durable facts 可以补全下一轮意图，但单独输入这些条件时仍不触发卡片。

## 关键改动

- 新增 `fix-blackbox-chat-flow-regressions` OpenSpec change，记录本轮 3 个失败的修复范围。
- `normalizeChatIntentForBlackboxFlows()` 增加推荐细化、空泛 plan 和历史条件事实继承分支。
- `resolveContextualWorkoutIntent()` 会把 `conversationContext.knownFacts` 合并进当前模型意图，再由当前消息覆盖字段。
- 单测新增 F01 第 3 轮、F05 第 1 轮、F07 第 2 轮的确定性覆盖，并补充每周计划补齐后保持 plan 语义的回归。

## 验证结果

- `npm run typecheck`：通过。
- `npm test`：32 个测试文件、166 个测试全部通过。
- `openspec validate fix-blackbox-chat-flow-regressions --strict`：通过。
