## 背景问题

动作推荐的“换一批”和替代动作选择之前主要依赖前端传 `excludeExerciseIds`，再由接口层临时过滤。候选不足时接口会清空排除条件回填高匹配动作，导致当前卡片动作可能再次出现，也不方便解释某个动作为什么被排除。

## 调整思路

把动作曝光、用户反馈、健康风险和未来过度使用统一下沉到 `selectExerciseCandidates`。候选服务负责生成排除集合、结构化排除原因、候选不足放宽策略和 `RecommendationTrace`，API、聊天上下文和 Patch 替代动作复用同一份服务端决策。

## 怎么做

- 新增 `ExerciseExposureSource`、`RecommendationTrace` 和 `RecommendationRelaxationOption` 类型。
- 将当前卡片曝光设为硬排除；当前会话曝光、近期推荐、未来计划高频动作和 `too_hard` 设为可放宽软约束。
- `dislike`、健康风险、器械不可用、section 不合法等继续作为硬限制，不能自动放宽。
- `/api/ai/exercise-recommendations` 不再清空排除集合回填旧动作；候选仍不足时返回 trace 和可确认的放宽选项。
- 聊天动作检索和 Patch 替代候选会把 `RecommendationTrace` 写入 AI trace。

## 结果

已补充候选服务和 API 边界测试，覆盖当前卡片不重复、`dislike`、`too_hard`、健康风险、软约束放宽和 trace 字段。相关测试 `npm test -- tests/workout-plan.test.ts tests/api-routes.test.ts` 通过，`npm run typecheck` 通过。
