# 恢复 DeepSeek V4 Flash Thinking Mode

时间：2026-06-06 02:41:13 CST

## 背景

Agent Loop 重构前，首页聊天请求直接使用 `deepseek-v4-flash`，并把前端 `thinkingEnabled` 映射为 DeepSeek provider 请求体中的 `thinking.type`。重构到 `LlmPlanner + DeepSeekModelAdapter` 后，前端开关和 `AgentRunInput.metadata.thinkingEnabled` 仍在，但 provider request 没有继续携带 `thinking`，默认模型也回退到旧的 `deepseek-chat`。

这会让界面上的思考模式开关失去真实效果，也让 `/dev/ai-traces` 无法判断本轮模型请求到底是否开启 Thinking Mode。

## 调整思路

本次不新增业务 tool、不改 `AgentAction` 合同、不接入 DeepSeek 原生 `tools/tool_calls`。修复边界只放在 provider adapter、集中配置、trace 投影和相关测试中：

- `lib/server/config/agent-runtime-config.ts` 统一声明 DeepSeek 默认模型 `deepseek-v4-flash`、Thinking Mode 默认开启和 `reasoning_effort = "high"`。
- `DeepSeekModelAdapter` 从 `run.metadata.thinkingEnabled` 读取受控开关，并映射为 `thinking.type = "enabled" | "disabled"`。
- `reasoning_content` 只作为 trace 诊断保留，不拼接进正式 `content`，不作为 `AgentAction` JSON 解析来源，也不进入用户可见 NDJSON。
- terminal failure finalizer 只做低延迟失败解释，显式发送 `thinking.type = "disabled"`。

## 关键改动

- 生产聊天默认模型恢复为 `deepseek-v4-flash`，`DEEPSEEK_MODEL` 仍可覆盖最终请求 model。
- 开启思考模式时请求体携带 `thinking.type = "enabled"` 和 `reasoning_effort = "high"`。
- 关闭思考模式时请求体显式携带 `thinking.type = "disabled"`，避免 provider 默认开启。
- `/dev/ai-traces` 的模型请求与响应诊断可以看到 thinking 配置、reasoning 是否返回、长度和摘要。
- README、Prompt 入口说明和手动 LLM 黑盒说明同步更新当前默认模型。

## 预期效果

开发者可以在 trace 和导出 log 中确认 `thinkingEnabled` 是否真实进入 DeepSeek provider request；用户可见聊天协议保持稳定，不新增 reasoning stream event，也不保存原始思维链到会话历史。
