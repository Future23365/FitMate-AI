# 移除医疗健康风险决策边界

## 真实问题

系统已经不再因为缺少健康信息主动追问，但用户主动提到疼痛、伤病、不适后，服务端仍会把这些信号转成候选排除、长期记忆约束、确认流或 Patch 替换拒绝。结果是用户已经决定训练时，系统仍可能因为医疗健康标签替用户阻断正常结果。

## 调整思路

把医疗健康信号从“训练生成决策”中移出。系统不再根据疼痛、伤病、不适、`injuryLimitations`、`riskTags` 或 `contraindications` 判断动作能不能选、计划能不能生成、替换能不能应用。保留的边界只是不输出医疗诊断或治疗承诺。

## 关键改动

- 动作候选筛选不再生成 `health_risk` 排除原因。
- 用户反馈记忆不再把健康/不适文本写成影响候选的 `injury_or_pain_signal`。
- Policy 不再因为健康信号要求长期记忆确认。
- Workout Patch 不再因为替代动作带高风险标签拒绝。
- 模型候选摘要不再暴露 `necessaryRestrictions` 风险字段。
- 文档和测试改成断言健康/医疗信号不阻断训练结果。

## 结果

训练生成只保留动作库事实、候选集合、section、器械、难度、时长、结构化校验、权限隔离等非医疗边界。用户身体状态由用户自行判断，系统不替用户做医疗健康决策。
