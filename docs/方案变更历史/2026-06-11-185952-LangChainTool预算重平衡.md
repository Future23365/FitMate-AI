# LangChain Tool 预算重平衡

时间：2026-06-11 18:59:52 CST

## 背景

生产 `/api/chat` 已迁移到 `LangChain Agent Runtime + DeepSeek native tool_calls` 后，Tool 调用预算仍主要依赖单个总量上限。旧配置下 `maxToolCalls = 5` 是所有业务工具共享的总预算：如果某一个 tool 因模型连续重试或重复调用消耗完 5 次，后续其他 tool 就没有可用调用空间。

这会让一次 Agent 运行的失败形态不稳定：问题不在于总次数是否被消耗，而在于单个 tool 可以占满共享预算，破坏后续工具的恢复能力。

## 调整思路

本次改为两层预算：

- 总业务 tool 调用预算提升到 20，用于覆盖一次复杂对话中多个资源查询、校验和保存动作。
- 每个业务 tool 增加独立单轮调用上限 2，避免单个 tool 的重复调用耗尽整轮预算。

每个 tool 的独立上限使用 LangChain 原生 `toolCallLimitMiddleware` 实现，运行态只负责按业务 tool 注册 middleware；不新增服务端自然语言分流、关键词规则或基于用户 phrasing 的特殊处理。

`reportAgentActivity` 属于运行态活动汇报工具，不纳入业务 tool 的单 tool 调用上限；它继续使用独立的 activity 预算。

## 关键改动

- `agentRuntimeConfig.langChain.runBudget.maxToolCalls` 从 5 调整为 20。
- 新增 `maxToolCallsPerTool = 2`，集中放入运行时配置。
- `maxModelCalls` 调整为 23，对应 20 次业务 tool、2 次 activity 和 1 次 final model call。
- LangChain runtime 为每个业务 tool 注册 `toolCallLimitMiddleware({ runLimit: 2, exitBehavior: "continue" })`。
- 系统 prompt 的运行预算说明同步暴露“每个业务工具最多 2 次调用”。
- 测试覆盖单 tool 上限、总预算上限、activity 不占业务 tool 上限、prompt 配置可见性和 graph recursion 预算。

## 结果

调整后，某一个业务 tool 最多只能在单轮运行中执行 2 次；即使模型继续请求同一个 tool，LangChain middleware 也会阻止该调用并把结果反馈回模型。其他业务 tool 仍然可以继续使用剩余总预算，避免第一个 tool 把整个 20 次预算耗尽。

验证命令：

```bash
openspec validate rebalance-langchain-tool-call-budget --strict
npm test -- tests/langchain-agent-runtime/runtime.test.ts tests/langchain-agent-runtime/config.test.ts
npm run typecheck
npm run lint
```
