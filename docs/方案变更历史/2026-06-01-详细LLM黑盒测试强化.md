# 详细 LLM 黑盒测试强化

记录时间：2026-06-01 00:01:59 CST

## 背景

原有详细套件已经能覆盖更多首页聊天流程，但 runner 仍偏轻量：它直接复用服务端聊天编排函数，并在内存里维护会话状态和 recent artifact summary。这样可以验证“能回答、能推卡片类型”，但不足以证明真实首页请求、匿名 current user、会话保存、`ConversationArtifact` / `ArtifactIndex` 写入和后续引用读取都可用。

## 调整思路

本次把详细套件的重心从 prompt 一致性推进到真实黑盒链路：

- 每轮使用接近首页的 `/api/chat` 请求字段。
- 使用测试专用匿名用户，确保聊天请求和会话保存使用同一个 current user。
- 每轮成功后保存用户消息、assistant 消息、summary、context 和可见训练卡片 payload。
- 后续引用类轮次依赖真实数据库 artifact summary 和 payload，而不是手工 recent summary。
- 报告分开记录卡片类型断言、语义断言、最终状态、失败等级和 artifact 诊断。

## 关键改动

- `manual-tests/llm/blackbox-runner.ts` 改为 `api_route` runner，负责 Route Handler 请求、NDJSON stream 消费、会话保存和 artifact 诊断。
- `manual-tests/llm/assertions.ts` 增加分级语义断言，覆盖引用成功、payload 可读性、必含/禁用关键词和引用失败短语。
- `manual-tests/llm/flow-fixtures.ts` 补齐 `LLM完整测试.md` 中高价值缺口，详细套件从 38 个流程扩展到 53 个流程。
- `scripts/run-manual-llm-tests.mjs` 的 token 预估改为优先用最近真实报告校准，缺失时使用 fixture 和轮次数 fallback。
- 报告新增运行命令、runner 类型、preflight、估算来源、token 偏差、断言分层和 artifact 诊断字段。

## 边界

真实模型运行仍需要用户显式提供 `DEEPSEEK_API_KEY`。缺 key 时只生成跳过报告，不使用 mock、旧快照或非真实模型结果。浏览器视觉、输入焦点、滚动和截图验收不纳入本次 change。
