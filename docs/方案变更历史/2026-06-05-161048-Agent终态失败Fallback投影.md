# 2026-06-05 16:10:48 CST Agent 终态失败 Fallback 投影

## 当前真实问题

生产 `/api/chat` 已经接入 `agent-core`、生产 `ToolRegistry` 和默认 NDJSON renderer，但 Agent 在 terminal output validation、repair budget 耗尽或预算超时时，用户可见层仍容易落到统一的“聊天生成失败，请稍后重试。”。这个文案把结构化训练输出未通过校验、能力未接入、配置不可用、超时和未分类异常混在一起，用户无法知道下一步该缩小范围、补充条件、改问普通问题还是稍后再试。

最新导出的 `codex_logs/ai_trace_log.js` 已被成功聊天覆盖，不再是本 change 的失败证据；本次实现用 OpenSpec 文档中的失败类型和可复现测试 fixture 固定回归。

## 调整思路

这次没有改 `agent-core` 默认 `Response Renderer` 的通用安全错误边界，而是在 production chat adapter 增加一层用户体验投影。分类只读取 `AgentRunResult.status`、`terminalError.code`、repair / budget trace、validator observation details 和 registry/tool capability 等确定性事实，不读取用户原文，也不根据具体 `toolName` 或 phrasing 做服务端语义分流。

## 关键改动

- production adapter 为可分类 terminal failure 输出安全 `content`、`assistant_suggestions` 和 `done`：
  - `unknown_tool` / unsupported capability 归类为能力未接入。
  - `repair_limit_exceeded` + visible output / terminal reference / section coverage 诊断归类为可靠训练结果未通过校验。
  - `overall_timeout`、`budget_exhausted` 等归类为步骤或信息量超出当前处理范围。
- 未分类错误仍输出 `error`，但 production 和前端都不再使用旧的不可恢复死路文案。
- trace 的 `response_write.output` 增加 `projectionType`，用于区分 `final_answer_success`、`unsupported_capability_fallback`、`visible_output_validation_fallback`、`budget_timeout_fallback`、`transport_config_failure` 和 `unclassified_error_event`。
- 前端 chat client 保留 HTTP、stream / NDJSON parse、abort / timeout 和 event error 防线，但只映射到安全中文文案，不展示 provider 原文、HTTP body、validator details 或 stack。
- `visibleTrainingProposal` validator 保持强校验：正文中提到热身、拉伸或处方建议，不能替代 `exerciseItems[]` 中可校验的 `warmup` / `stretch` 动作事实。

## 结果

用户可见 terminal failure 不再落到统一“聊天生成失败”文案；可恢复失败会以普通 assistant message 落地，并附带下一步建议。内部 trace 仍保留原始错误 code 和分类，方便继续排查真正的 runtime、validator 或 provider 问题。
