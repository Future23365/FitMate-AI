# 恢复基础 LLM 黑盒手动入口

记录时间：2026-06-05 17:46:05 +0800

## 当前真实问题

基础首页聊天黑盒套件曾经通过 `npm run test:llm:basic` 独立运行，但在合并后清理旧黑盒入口时被一并删除，导致 `llm基础测试.md` 只保留人工用例，没有可执行 runner、judge、report 和专用命令。

同时，默认测试目录中保留了一个可通过 `RUN_DEEPSEEK_BLACKBOX=1` 触发真实 DeepSeek 调用的 fixture blackbox。虽然它平时跳过，但只要环境变量存在，`npm run test` 就可能消费模型 token。这和当前协作边界冲突：Codex 完成需求后的自动化验证不能真实调用模型 API。

## 调整思路

本次把真实模型测试重新收口为“手动入口”：

- 默认 `npm run test` 只运行普通 Vitest 自动化测试。
- 所有会调用模型 API 的首页聊天黑盒测试只放在 `manual-tests/llm/**/*.manual.test.ts`。
- `npm run test:llm:basic` 通过独立 `vitest.manual-llm.config.ts` 运行，不进入默认 test discovery。
- 默认测试目录中不再保留 `RUN_DEEPSEEK_BLACKBOX` 这类真实模型 opt-in 执行分支。

## 关键改动

- 恢复基础黑盒 fixture、runner、judge 和 report，使其从 `llm基础测试.md` 动态读取三轮流程。
- 恢复 `scripts/run-basic-llm-blackbox.mjs` 和 `test:llm:basic` 命令，支持 `--flow`、`--report` 和 `--help`。
- 移除默认 `tests/agent-core/deepseek-fixture-blackbox.test.ts` 中的真实模型调用路径。
- 新增普通隔离单测，防止真实模型 opt-in 分支再次进入默认测试目录。
- 新增 `docs/manual-llm-basic-blackbox-tests.md` 说明命令、参数、环境变量、报告路径、token 成本和失败排查方式。

## 为什么不是放回 npm run test

首页聊天黑盒测试需要真实模型和 judge，必然消耗 token，并且受外部模型、网络、本地数据库和匿名 auth 环境影响。把它放入默认测试会让日常验证和 Codex 自动验证不稳定，也会产生非预期成本。

因此默认测试只验证结构、合同和隔离边界；真实模型验收由开发者手动触发。

## 验证方式

- `npm run test -- tests/manual-llm-basic-blackbox.test.ts tests/agent-core/deepseek-fixture-blackbox.test.ts`
- `npm run test`
- `npm run test:llm:basic -- --help`
- `openspec validate restore-manual-llm-basic-blackbox-tests --strict`

其中只有 `npm run test:llm:basic` 的非 `--help` 运行会真实调用模型。
