# 聊天旧 Stream 合同收尾

记录时间：2026-06-03 11:44:58 +0800

## 问题背景

旧 Agent Core 运行时删除后，`/api/chat` 已经只返回普通 JSON 的 `chat_ai_disabled` 禁用响应，但首页聊天前端仍保留 `requestChatStream()` 命名、`response.body.getReader()` NDJSON 读取和 `ChatStreamEvent` 中的 artifact / patch / reference diagnostic 事件类型。

这些代码不会再被当前后端触发，但会误导后续开发：页面看起来仍支持旧 Agent stream、旧 artifact 事件和旧 patch 事件，实际运行时却已经没有对应生产者。

## 调整思路

本次继续遵守旧运行时 delete-only 边界，不重建 AI、不伪造 stream、不保留兼容 adapter。首页聊天前端到 `/api/chat` 的调用收敛为普通 JSON 请求，并直接展示禁用状态。

已保存历史消息、历史卡片和本地建议按钮继续保留；它们只来自本地会话状态或已保存数据，不再从旧 Agent stream 动态写入。

## 关键改动

- 将 `requestChatStream()` 替换为 `requestDisabledChatResponse()`，删除聊天请求的 raw stream 响应消费。
- 删除 `ChatStreamEvent`、artifact stream event、patch stream event 和 reference diagnostic stream event 类型。
- 将建议适配层改为只消费消息上的统一 `assistantSuggestions` 和历史 `suggestedReplies` / `suggestedQuestions` 字段。
- 更新聊天链路文档和 OpenSpec tasks，明确前端当前只消费普通 JSON 禁用响应。
- 增加旧接口清理测试，防止 `requestChatStream`、`ChatStreamEvent`、旧 artifact stream 事件和 `response.body.getReader()` 回到生产前端。
- 删除旧 `app/api/ai` 和 `manual-tests` 空目录，并修正时间格式扫描测试对已删除历史目录的处理。

## 结果

首页聊天前端不再保留旧 NDJSON stream parser 和旧 Agent 事件消费合同。当前聊天链路只剩页面壳、历史会话、本地状态和 `/api/chat` 的普通 JSON 禁用响应；后续重新接入 AI 时需要重新定义前端事件协议。
