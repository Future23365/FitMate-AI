# 可见训练方案刷新合同收紧

时间：2026-06-04 23:54:15 CST

## 问题

最新刷新链路暴露出一个模型可见合同缺口：`recentVisibleTrainingProposals` 已收敛为轻量索引，`inspectVisibleTrainingProposals(read_recent)` 也能导入上一套可见方案事实，但 Planner 仍可能按原始需求和同一排序重新查询动作，生成与上一套用户已看到动作高度重复的 `routine` / `plan`。

这个问题不适合在 `/api/chat`、Agent core 或 tool handler 中写“换一批”“重新来一套”之类的服务端短语分流。根因是模型实际可见输入没有把 `visibleTrainingProposal` 刷新的结果语义讲清楚：刷新应保留原目标和约束，同时优先替换上一套用户已看到的 `exerciseItems`。

## 调整思路

把修复放在模型可见合同里，而不是新增业务编排分支：

- 通用 AgentAction system prompt 说明 `visibleTrainingProposal` 的刷新结果要求。
- `inspectVisibleTrainingProposals` manifest 和 `read_recent` observation 说明读取上一套事实是为了后续差异化刷新，不代表已经生成新方案。
- `searchExerciseResources` manifest 和 observation 说明 `excludeExerciseIds` 的来源只能是当前 run 可见的用户已看到动作事实或用户明确排除项。
- 候选不足时允许说明无法完全换新、询问是否放宽条件或只输出可支撑结构，但不能回填已排除动作后声称已经换新。

服务端仍只做 schema、权限、数据库事实、resource 和 terminal validation，不根据用户原文替模型选择 tool、action 或 `payload.kind`。

## 关键改动

- `agentLlmPromptVersion` 升级到 `agent-action-v7`。
- `agent-llm-prompt-config.ts` 增加可见训练方案刷新语义：保留目标 / 器械 / 难度 / 居家条件 / 时长 / section / 计划约束，优先替换上一套用户已看到动作。
- `inspectVisibleTrainingProposals` 说明读取事实可用于保留、排除、替换、查询新动作、调整结构、澄清或失败收口；`read_recent` observation 明确本 tool 不生成新 `visibleTrainingProposal`。
- `searchExerciseResources` 说明替换动作时可用 `excludeExerciseIds` 查询替代动作，但排除集合不得来自未展示内部候选、trace 摘要、handler-only 结果或未读取完整事实。
- 新增架构扫描，确认刷新短语没有进入 `/api/chat`、Agent core、renderer 的服务端分流。
