# 2026-06-04 01:58:25 CST AiTrace 双文件导出

## 原问题

`/dev/ai-traces` 的「保存全链路log」原本把结构化摘要、Raw trace 和长文本都写进 `codex_logs/ai_trace_log.js`。这让默认排查入口很重；如果继续靠长度硬截，又会丢掉 prompt 尾部约束、tool observation 尾部反馈或模型 JSON 结尾，影响排查模型行为 bug。

## 调整思路

默认报告应该服务于快速定位：先看 loop、step、tool、error code、token usage、response summary 和关键 id。长 prompt、model input、observation、raw response 等只在需要时按引用读取。

## 关键改动

- 「保存全链路log」改为覆盖写入两份文件：
  - `codex_logs/ai_trace_log.js`：轻量报告，保留结构化摘要和 `contentRef`。
  - `codex_logs/ai_trace_texts.jsonl`：长文本映射，一行一个脱敏长文本记录。
- 报告中的长文本引用包含 `contentRef`、`path`、`kind`、`originalLength`、`hash` 和 `preview`。
- 两个导出文件头部都加入查询说明，默认先读报告；需要长文本时用 `rg '"contentRef":"text_0001"' codex_logs/ai_trace_texts.jsonl` 定位。
- 服务端继续脱敏，并额外防止 `payload`、`handler`、`database`、`tool_output` 等敏感路径通过长文本映射绕过脱敏。

## 边界

本次只修改开发态 trace 导出格式，不修改 `/api/chat`、Agent runtime、Planner、ToolRegistry、Policy Guard、ResourceStore、Response Renderer、模型实际输入或用户可见聊天协议。
