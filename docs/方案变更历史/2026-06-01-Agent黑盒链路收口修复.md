# 2026-06-01 23:19:49 CST Agent 黑盒链路收口修复

## 背景

Tool-first Domain Agent Orchestrator 切换到主链后，最新首页 LLM 黑盒报告暴露出核心链路不是单点失败，而是 Agent tool result 到用户可见卡片之间的收口缺口：动作推荐、routine 生成和 plan 生成都已经触发工具，但最终结果没有稳定落到 artifact 或推荐卡片。

## 原方案问题

- 推荐链路过度依赖 Agent final result 的 `usedToolResultIds`，模型漏写引用时，已成功的 `searchExercises(candidateUse="recommendation")` 无法投影成卡片。
- 首次创建 routine/plan 仍沿用 revision 写入思路，要求已有 `sourceArtifactId`，导致首次生成训练内容无法保存为新的聊天 artifact。
- `generatePlanDraft` 强制依赖已有 routine/plan artifact，不支持用户第一次要求生成长期计划。
- Validator 把 `isRestDay = true` 的恢复日也按用户单次训练时长做 `session_too_short` 硬失败，导致包含休息日的长期计划被错误拦截。
- 黑盒 runner 把 Agent 的 `answered` 状态也计入可见卡片类型，训练卡片已出现时仍可能被误判为多出 `answer`。

## 调整思路

修复方向是保留 Tool-first Agent 的资源合同，不回退到旧 intent-first 语义判断。服务端只使用本轮工具产物和结构化 resource id 进行投影、校验与保存：推荐卡来自推荐用途的候选集合，draft/validation/policy/save 之间通过本轮 tool result 解析，首次生成内容时创建新的 `ConversationArtifact`。

## 关键改动

- `searchExercises` 增加短 facet 别名恢复，覆盖 `胸`、`胸肌` 等常见模型入参。
- 推荐卡片投影允许从本轮成功的 recommendation candidate set 兜底，但不从用户原文或旧 intent 重解释语义。
- `evaluatePolicy` 支持 `new_artifact` 目标，`saveConversationArtifactRevision` 在无 source artifact 时可以创建新的 routine/plan artifact。
- `generatePlanDraft` 在首次生成时可用候选动作构造 seed routine，再交给 `DomainPlanEngine` 展开长期计划。
- 训练计划 Validator 的单次时长硬约束只作用于非休息训练日。
- 黑盒 runner 在训练卡片出现时过滤同轮 `answer` 状态，避免报告误判。
