# 可见训练方案富卡片接入

记录时间：2026-06-04 19:38:59 CST

## 当前真实问题

`/api/chat` 已经把动作推荐、单次训练编排和长期训练计划统一输出到 `final_answer.visibleOutputs[]` 的 `visibleTrainingProposal`，但聊天页仍把这份结构化事实展示成临时的 `VisibleTrainingProposalPanel`。这个轻量面板只适合验证新链路，会泄漏 `exercise_selection` / `routine` / `plan` 这类技术枚举，也绕开了项目里已经成熟的三张训练富卡片。

同时，前端还保留旧 `bubblePlans`、`bubbleRoutines`、`bubbleExerciseRecommendations` 的渲染、保存和恢复路径。继续保留两套训练事实入口，会让用户看到的卡片、模型可引用的事实和聊天历史保存内容再次分叉。

## 调整思路

本次只改前端消费层：`visibleTrainingProposal.payload` 继续作为唯一训练事实源，前端新增 adapter 把它派生为旧三张富卡片需要的视图模型。`content` 只用于补充动作名称、图片、器械、肌群等展示详情；缺失详情时使用稳定兜底或让旧卡片通过 `/api/exercises/:id` 补齐，不反写 `payload`。

旧 `bubble*` 历史兼容路径直接停用，不做迁移、双写或运行时 fallback。推荐按钮能力保持预留，本次不把 `assistantSuggestions` 绑定到训练富卡片底部。

## 关键改动

- 新增 `features/chat/lib/visible-training-proposal-cards.ts`，集中把 `exercise_selection`、`routine`、`plan` 投影为 `ExerciseRecommendationCard`、`WorkoutRoutineDraftCard`、`WorkoutPlanDraftCard` 的数据结构。
- `ChatPage` 删除 `VisibleTrainingProposalPanel` 及其轻量列表、处方 chip、技术枚举 badge，改为从 `message.visibleOutputs` 渲染旧三张富卡片。
- `use-chat-controller` 不再维护或恢复 `bubblePlans`、`bubbleRoutines`、`bubbleExerciseRecommendations` 等旧状态。
- `chat-history` 保存白名单收敛为消息、`visibleOutputs`、对话摘要和上下文，不再保存旧 `plans` / `routines` / `exerciseRecommendations` / `recommendationIntents`。
- 增加 adapter、controller、聊天页渲染和客户端保存 payload 测试，覆盖三种 `kind`、旧 fallback 退出、训练日复用同一套编排、休息日来自 `schedule.assignments`。
