# 可见训练方案富卡片补漏

记录时间：2026-06-04 19:53:36 CST

## 当前真实问题

第一次富卡片接入后，真实聊天里“推荐一批动作”仍可能没有卡片。trace 显示 `/api/chat` 已经发出 `visible_output`，问题不是服务端没有生成 `visibleTrainingProposal`，而是旧 `ExerciseRecommendationCard` schema 最多允许 10 个动作；当 `searchExerciseResources` 返回 12 个动作时，adapter 直接 `safeParse` 12 个 item 后返回 `null`。

另一个遗漏是聊天历史服务端持久化。客户端保存 payload 已带 `message.visibleOutputs`，但 `chat-history-service` 没有把它写入 `chatMessage.metadata`，读取历史时也没有还原到 `ChatMessage.visibleOutputs`。刷新或重新进入会话后，新事实源会丢失。服务端还会从旧 metadata 重新组装 `plans` / `routines` / `exerciseRecommendations` / `recommendationIntents`，导致旧历史数据仍然对外暴露。

## 调整思路

前端 adapter 继续只派生旧三张富卡片视图，不改变 AI payload 合同。推荐动作卡片 schema 上限调整为与 `visibleTrainingProposal.exerciseItems` 一致的 40 个，AI 输出多少个动作项，前端就展示多少个动作项。

服务端聊天历史改为只保存和恢复 `visibleOutputs`、建议回复、摘要和上下文；旧 `plans` / `routines` / `exerciseRecommendations` / `recommendationIntents` metadata 不再保存、不再恢复、不再创建旧 conversation artifact。

## 关键改动

- `exerciseRecommendationCardSchema` 将动作展示上限扩展到 40，`visible-training-proposal-cards` 不再截断 `exercise_selection` 展示项。
- `chat-history-service` 保存消息 metadata 时写入 `visibleOutputs`，并通过 JSON 序列化投影保证 Prisma JSON 可写。
- `chat-history-service` 读取历史时从 metadata 恢复 `visibleOutputs`，忽略旧 bubble metadata。
- 删除服务端旧 `plans` / `routines` / `exerciseRecommendations` artifact 创建路径。
- 更新 adapter 和 persistence 测试，覆盖 12 个推荐动作完整展示、服务端 visibleOutputs 保存/恢复、旧 metadata 不回流。
