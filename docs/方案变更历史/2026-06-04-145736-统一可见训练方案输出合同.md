# 2026-06-04 14:57:36 CST 统一可见训练方案输出合同

## 问题

旧动作刷新事实桥把 `searchExerciseResources` 的用户投影当成下一轮推荐事实来源，`displayedExerciseIds`、`exercise_recommendation_displayed` 和 `readRecentExerciseRecommendationFact` 只能表达“上一轮展示了哪些动作”，无法承载一次训练编排、长期计划、处方和 schedule。继续沿用这条链路会让候选查询事实、用户可见训练方案事实和跨 run read/import 事实混在一起。

## 调整思路

本次把“用户实际看到的训练内容”统一收敛到 `final_answer.visibleOutputs[]`。Agent core 只认识通用 envelope，业务层通过 `visibleTrainingProposal` validator 和 renderer 校验、渲染、保存事实。`searchExerciseResources` 降级为只读动作事实候选查询，返回按 `warmup`、`training`、`stretch` 分组的 `exerciseId` 候选，不再承载最终方案事实。

## 关键改动

- 新增 `final_answer.visibleOutputs[]` 通用结构化输出 envelope。
- 新增 `visibleTrainingProposal` payload，覆盖 `exercise_selection`、`routine` 和 `plan`。
- 新增 `visible_training_proposal_displayed` / `visible_training_proposal_fact` 事实桥和 `readRecentVisibleTrainingProposal` read/import tool。
- 删除旧 `exercise_recommendation_*` 事实桥主路径和旧 read tool，不提供 alias 或兼容读取。
- `searchExerciseResources` 删除模型可传的旧单值 `suitability` input，改为 `suitabilities[]`，候选输出统一使用 `exerciseId`。
- 聊天气泡开始渲染 `visibleTrainingProposal` 结构化输出，不从正文或旧 trigger 反推训练事实。

## 验证

本次新增 core validator/renderer、业务 validator、fact store、read tool、search tool 和聊天服务测试，用于覆盖 envelope 分发、业务 payload 校验、跨 run 事实桥、旧命名 delete-only 边界和用户可见渲染路径。
