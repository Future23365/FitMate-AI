# 2026-06-04 15:25:52 CST 可见训练方案事实引用边界修复

## 问题

`visibleTrainingProposal` 落地后，下一轮 run 会把最近可见方案的轻量摘要放进 `run.metadata.recentVisibleTrainingProposals`。这份 metadata 的本意是给模型提供 `factRef` / `messageId` 索引，方便按需调用 `readRecentVisibleTrainingProposal` 把完整事实导入当前 run。

实际实现里，terminal output validator 同时把 metadata summary 里的 `exerciseItems` 当成了最终方案可引用的动作来源；system prompt 也提示模型可以直接从 `recentVisibleTrainingProposals` 复制 `exerciseId`。这样会绕过 `readRecentVisibleTrainingProposal` 的 read/import resource 边界，也绕过读取完整事实时对动作仍存在于数据库中的复验。

## 调整思路

本次把 metadata summary 明确收窄为“历史事实索引”，不再承担“当前 run 可消费事实源”职责：

- `recentVisibleTrainingProposals` 只提供 `factRef` / `messageId`，不能直接支撑 `visibleTrainingProposal.exerciseItems[*].exerciseId`。
- 复用历史方案动作时，必须先通过 `readRecentVisibleTrainingProposal` 导入当前 run。
- `readRecentVisibleTrainingProposal` 在读数据库前先校验输入引用确实出现在当前 run metadata 中；不存在时返回结构化 failed output，不访问 fact store。
- terminal output validator 只接受本轮 satisfied `searchExerciseResources`、已导入的 `readRecentVisibleTrainingProposal` tool result，或当前 run `visible_training_proposal_fact` consumable resource 作为动作来源。

## 关键改动

- 移除 `visible-training-proposal-validator` 对 `run.metadata.recentVisibleTrainingProposals.exerciseItems` 的直接采信。
- 收紧 `readRecentVisibleTrainingProposal` handler 的确定性引用校验，防止模型猜测或复用不在当前 run metadata 中的 `factRef` / `messageId`。
- 更新 system prompt，说明 metadata 只提供索引，历史动作 id 必须来自已导入的 `visible_training_proposal_fact`。
- 补充 validator、tool、chat service 和 prompt 回归测试。

## 结果

历史训练方案复用链路回到单一事实桥：轻量 metadata 负责索引，完整事实通过 read/import tool 进入当前 run，再由 `ResourceStore` 和 terminal output validation 支撑最终用户可见训练方案。这样比在 metadata 路径上补数据库查询更清晰，也避免同一份 summary 同时扮演索引和事实源。
