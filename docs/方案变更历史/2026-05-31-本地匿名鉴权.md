# 2026-05-31 本地匿名鉴权

## 原方案问题

服务端此前通过 `local-demo-user` 固定用户承载所有聊天、训练编排、训练日历、artifact 和用户记忆数据。这个方案适合早期本地验证，但无法区分不同浏览器或不同使用者，也会让后续接入正式注册登录时重新调整所有 API 边界。

## 调整思路

本次先不引入邮箱密码、OAuth 或完整账号系统，而是把“当前用户是谁”提前收敛为请求级鉴权上下文。浏览器首次进入应用时创建本地匿名身份，前端保存服务端签发的匿名 token；后续私有 API 请求统一携带 token，服务端通过 `UserIdentity(provider = "anonymous")` 恢复当前用户。

## 关键改动

- 新增服务端本地匿名 token 签发和校验逻辑，token 只携带匿名主体 id，不信任客户端传入的裸 `userId`。
- 新增 `POST /api/auth/local-anonymous`，用于创建或恢复匿名会话。
- Route Handler 在调用业务服务前统一解析 `CurrentUser`，缺少或无效凭证时返回 `401 unauthenticated`。
- 前端新增应用级本地 auth gate，auth ready 前不挂载侧栏和页面，避免提前请求私有 API。
- 统一请求层自动注入匿名凭证，并在收到 `401 unauthenticated` 时清理凭证、回到登录弹窗。
- 设置页新增“重置本地用户”，只清理当前浏览器凭证，不删除旧用户数据。

## 限制

本地匿名 token 不是正式账号体系，无法跨设备同步，也不支持单个会话撤销。后续接入正式登录时应优先考虑 HttpOnly cookie、账号绑定和匿名数据迁移策略。
