# 2026-06-02 20:17:05 CST 本地动作图片展示 URL

## 背景

动作图片已经由脚本下载到 `exercises_picture/<Exercise.id>/`，但服务端仍把 PostgreSQL 中的原始 GitHub raw URL 直接返回给前端。这样会让动作库、推荐卡和训练执行页继续依赖第三方图片源，也不利于后续迁移到 CDN 或对象存储。

## 调整思路

本次把动作图片展示 URL 收敛到服务端数据出口：数据库继续保存原始 `images` / `imageUrls`，服务端根据 `exercises_picture/_manifest.json` 和环境变量派生当前展示 URL。前端不再需要知道图片来源是 GitHub、本地 API 还是外部静态资源。

## 关键改动

- 新增 `EXERCISE_IMAGE_LOCAL_DIR` 和 `EXERCISE_IMAGE_PUBLIC_BASE_URL` 配置，默认分别为 `exercises_picture` 与 `/api/exercise-images`。
- 新增动作图片 resolver，优先读取 `_manifest.json`，按动作 id 和步骤序号输出稳定 URL，并在资源缺失时回退占位图。
- 新增 `/api/exercise-images/[...path]` Route，只允许读取配置目录内的图片文件，并拒绝路径穿越、非图片后缀和目录外文件。
- 动作库 repository 与已保存 routine / schedule 读取链路复用同一 resolver，保证推荐卡和训练执行页消费统一展示 URL。

## 结果

默认展示地址从 GitHub raw URL 切换为站内 `/api/exercise-images/...`。后续如迁移 CDN，只需要调整 `EXERCISE_IMAGE_PUBLIC_BASE_URL`，不需要重写数据库图片字段。
