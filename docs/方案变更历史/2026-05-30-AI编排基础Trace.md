# AI 编排基础 Trace

## 当前问题

Artifact、引用解析和 Patch 接入后，一次聊天请求可能在多个阶段出错：引用可能没有定位到正确卡片，受控工具可能没有读到 payload，Patch 可能被边界校验拦截，训练草稿也可能在校验或持久化阶段失败。旧 trace 主要围绕模型请求、动作候选和最终返回，开发者能看到部分现象，但很难复盘“为什么选中了这个 artifact”“为什么 Patch 没应用”“失败是可恢复还是硬失败”。

## 调整思路

这次把现有开发态 `AiTrace` 扩展成 `AiRunTrace` envelope，不新建外部观测平台，也不改变前端拿 `traceId` 的主契约。trace 顶层记录 `runId`、`userId`、`sessionId`、`messageId`、模型、`promptVersion`、`toolVersions`、输入摘要和 `finalDecision`；step 层新增 `reference_resolution`、`tool_call`、`patch_proposal`、`persistence` 和 `response_write`。

## 具体做法

- 在 trace store 层统一做敏感字段脱敏和长字段截断，避免 API key、Authorization、超长 payload 进入调试日志。
- `/api/chat` 创建 trace 时写入用户、会话、消息、模型、prompt 和 recent artifact 摘要。
- ReferenceResolver 记录近指引用、语义检索、歧义和未找到状态；`searchArtifacts` 作为受控工具记录输入和候选摘要。
- Patch 链路记录 `getArtifactPayload`、Patch 提出、结构校验、边界校验、revision 持久化和最终应用结果。
- `/dev/ai-traces` 将新增 step 映射为可读阶段，并继续保留阶段、单 step 和全链路 Raw JSON 保存能力。

## Trace 页面收尾完善

第一版页面虽然已经能展示新增 step，但仍存在三个调试成本较高的问题：请求概览默认展开挤占主要链路；流程步骤和内容主体分离，需要先点阶段再滑到下方；计划草稿、模型 prompt 和 preview 只藏在模型请求参数里，阅读成本高。

这次页面改为纵向阶段流：每个阶段卡片默认收起，只展示阶段状态、耗时、token 和事件数量，方便先找模块；展开某个阶段后，当前阶段下方直接包含事件列表、重点字段解释、模型 prompt、计划草稿摘要和 Raw JSON。请求概览默认收起，只在核对入口、权限和 metadata 时展开。阶段内部的失败事件、错误事件和草稿生成事件默认展开，方便先看最可能影响结果的节点。

重点调试信息从 Raw JSON 中提出来单独显示：

- `model_request` 展示模型配置、system prompt、user prompt，以及可识别 JSON 上下文中的 `latestUserMessage`、`conversationSummary`、`intent`、`validation`、`recovery` 和候选动作池数量。
- 所有发送给模型的 `message.content` 都像模型回复一样单独纵向展示；结构化 preview 另起区域，不再和长文本堆在同一块横向内容里。
- routine / plan 草稿展示标题、`kind`、预计时长、周期天数、训练日/休息日、阶段和动作摘要。
- step 解释区突出 `toolName`、候选数量、Patch `operation`、校验错误、持久化 revision、最终响应长度和 token usage。

字段阅读顺序建议：

1. 先扫收起的阶段列表，按 `status`、事件数、耗时和 token 找到可疑模块。
2. 展开可疑模块，优先看失败事件或默认展开的草稿生成事件，确认 `code`、`message` 和 `error`。
3. 再看模型请求的 prompt 和候选池摘要，确认模型是否收到了正确上下文。
4. 如果是计划草稿问题，直接看“计划草稿重点”，再对照 validation 的 `errors`。
5. 最后展开 Raw JSON 或保存 log，检查低频字段和完整 payload。

## 结果

第一批 AI 编排 trace 已覆盖 artifact 摘要、引用解析、受控工具、Patch、校验、持久化和响应写入。失败路径能记录权限拒绝、候选不足、Patch 校验失败、持久化失败以及最终决策类型；trace 写入异常不会阻断用户可见回复。调试页现在以阶段为操作单位展示内容，开发者能在当前步骤下直接看到 prompt、草稿、重点字段和 Raw JSON，减少来回跳转和手动解析成本。
