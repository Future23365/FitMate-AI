# 2026-05-31 本地用户重置软删除

## 原方案问题

设置页“重置本地用户”的文案暗示旧匿名用户会被删除，但服务端实际只清除当前浏览器 cookie。这样会留下两个问题：用户以为旧身份已经不可用，旧 cookie 却仍可能恢复；后续排查训练、聊天和 trace 数据时，也无法判断某个匿名用户是否已经被用户主动重置。

## 调整思路

本次把重置定义为用户级软删除：旧 `User` 和关联业务数据保留，`User.deletedAt` 记录该身份已经退出当前生命周期。服务端恢复匿名会话和私有 API 当前用户解析都会过滤软删除用户，因此即使浏览器或代理再次带上旧 cookie，也只能按未认证处理并走新的匿名登录流程。

## 关键改动

- `User` 新增 `deletedAt` 字段和索引，迁移不物理删除任何历史数据。
- `DELETE /api/auth/local-anonymous` 只根据已签名 HttpOnly cookie 定位当前匿名 identity，幂等标记旧用户为软删除并清除 cookie。
- `restoreLocalAnonymousSession()` 和 `requireCurrentUser()` 不再返回 `deletedAt != null` 的用户，避免旧 cookie 继续访问旧用户私有数据。
- 设置页重置入口改为二次确认，确认文案明确说明软删除、当前浏览器退出旧用户、旧 cookie 无法恢复。

## 验证

服务端测试覆盖有效 cookie 软删除、软删除用户恢复失败、私有 API 当前用户解析未认证、缺失或无效 cookie 不创建用户也不误删其他用户。设置页测试覆盖确认弹窗接入和不直接调用重置接口。
