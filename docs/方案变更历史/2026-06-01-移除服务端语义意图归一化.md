## 2026-06-01 13:09:23 CST

本次调整解决聊天主链路中服务端越界理解自然语言的问题。旧方案在 LLM 已经输出结构化意图后，仍会用“换成”“改成”“每周”等关键词和历史摘要重新决定高层 action，曾把正确的 `exercise_replacement` 改写成 `routine`，导致局部替换退化为整套训练重新生成。

新的边界是：LLM 负责 `type`、`action.kind`、`workoutIntent.intentType` 等语义判断；服务端只做 schema、空值、字段一致性、引用需求、权限、数据库存在性、候选来源和 patch 范围校验。解析失败 fallback 只返回安全非执行意图，不再靠关键词产生可执行 action。

关键改动：

- 停止调用旧的 `normalizeChatIntentForBlackboxFlows` 语义归一化分支，替换为只处理非语义出口整理的契约处理。
- `createFallbackChatIntent` 改为安全非执行兜底。
- 引用解析和 Workout Patch 入口改为由 `action.kind` / `referenceRequirement` 驱动，关键词只用于 patch operation 或目标定位辅助。
- 引用型 action 缺少 `workoutIntent` 时不再被执行门控误判为缺少生成字段。
- 更新测试，删除旧的“服务端按短句改写高层意图”断言，增加引用型动作、fallback 和关键词不抢占生成型 action 的回归覆盖。
