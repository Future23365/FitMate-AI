# 详细 LLM 黑盒套件去重与提速

时间：2026-06-01 14:20:58 CST

## 背景

详细 LLM 黑盒套件已经扩展到 53 个三轮 flow。完整运行可以覆盖真实首页聊天链路，但每次都需要 159 轮真实模型调用，最近一次完整运行超过 160 万 token。套件继续靠堆用例增长后，日常定位失败会变慢，也更难判断某个 flow 为什么必须存在。

## 原方案的问题

原方案把基础与详细 flow 混在同一个顺序列表里，只有 `basic/detail` 两层入口。脚本里还硬编码了基础 9 个、详细 53 个 flow 和固定轮次数，导致 fixture 变更后 token 预估、跳过报告和控制台摘要容易失真。

详细用例中还存在严格重复和高重叠路径，例如 `F03` / `C06`、`W08` / `M03`。这些重复有些只是历史堆叠，有些承载了不同语义断言，但之前没有结构化说明。

## 调整思路

本次把详细套件治理成可分层、可筛选、可并发但仍保持真实黑盒性质的体系：

- 每个 flow 增加 `suite`、`groups`、`riskLevel` 和覆盖说明，用结构化元数据替代 id 前缀推断。
- 建立重复矩阵，记录严格重复、重复起点和高重叠 setup 的处理原因。
- 改写 `F03` / `C06`、`W08` / `M03` 的严格重复输入，保留“不重复追问”和 patch 后继续降级等独有断言。
- runner 支持按 flow id、group、suite 和最近报告失败 flow 重跑。
- 并发只发生在 flow 级别，同一 flow 内三轮对话继续串行。
- 报告记录完整 fixture 数、本次筛选数、筛选条件、未运行原因、并发数和去重检查摘要。

## 关键改动

- `manual-tests/llm/flow-fixtures.ts`：补齐元数据、重复矩阵和严格重复改写。
- `manual-tests/llm/flow-selection.ts`：新增子集筛选和 `failed-from-report` 解析。
- `manual-tests/llm/flow-governance.ts`：新增不调用模型的 fixture 元数据与重复检测。
- `manual-tests/llm/flow-execution.ts`：新增 flow 级并发队列，保持结果按 fixture 顺序输出。
- `manual-tests/llm/llm-consistency.test.ts`：改为先筛选和 preflight，再按 flow 队列执行并写动态范围报告。
- `scripts/run-manual-llm-tests.mjs`：移除硬编码规模和重复 token 估算，只解析参数并把运行条件传给 Vitest runner。

## 结果

完整详细套件仍可运行 53 个 flow，但日常排查可以只运行某个能力分组、某几个 flow 或最近失败 flow。缺少 `DEEPSEEK_API_KEY` 时会按筛选后的集合生成跳过报告，不请求真实模型。新增的本地测试可在不调用真实模型的情况下校验 fixture 元数据、重复治理、筛选策略、失败报告解析和并发顺序。
