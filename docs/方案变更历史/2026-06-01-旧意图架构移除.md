# 旧意图架构移除

记录时间：2026-06-01 19:13:10 CST

## 原问题

`/api/chat` 已经切到 Tool-first `AgentOrchestrator`，但生产模块里仍保留旧 `ResolvedChatIntent`、旧 action gate、`LegacyChatEventAdapter`、独立 `runReadonlyToolLoop` 和旧黑盒 action 解析。它们虽然多数不再是主入口，但继续存在于生产导出边界，会让后续开发误以为系统还有 intent-first 第二主链。

## 调整思路

本次清理按 deny-by-default 处理旧架构：生产聊天入口只保留 Agent context、Agent tool registry、Agent runtime、Response Writer、artifact / patch 事件和 `done` metadata。旧事件和旧只读 loop 不再由生产代码导出；黑盒 runner 改为只从 `AgentExecutionResult`、dependency graph、artifact / patch 事件和 legacy path absence 判断结果。

## 关键改动

- 重写 `lib/server/chat/chat-service.ts`，移除旧 intent schema、resolved intent repair、旧 action gate、旧只读 loop 接入和旧 `assistant_action` / `intent_resolved` 派生。
- 删除 `LegacyChatEventAdapter` 和独立只读 loop 源码导出，将读工具验证迁移到统一 Agent registry。
- 前端流解析和手动 LLM runner 不再消费旧 action 事件。
- Agent trace 的 `legacyPathSkip` 增加 `readonlyToolLoop` 和 `assistantActionEvent` 缺席证据。
- 测试迁移为 Agent-only stream contract、Agent registry 读工具、旧路径缺席和手动黑盒 policy 断言。
