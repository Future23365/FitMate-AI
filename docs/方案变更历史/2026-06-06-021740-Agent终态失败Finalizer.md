# Agent 终态失败 Finalizer

时间：2026-06-06 02:17:40 CST

## 背景

此前 `/api/chat` 已经能把部分 terminal validation / repair exhausted 失败投影成确定性中文 fallback，避免前端直接展示“聊天生成失败”。但这个 fallback 只能表达固定错误边界：当主 Agent 已经多次尝试、因为 validator 或 resource/visible output 合同失败而耗尽 repair budget 时，用户看到的是安全但机械的回复，难以自然继续对话。

这个问题不能通过放宽 `Action Validator`、terminal output validator 或前端卡片兜底解决。无效 `visibleOutputs[]` 仍然不能展示、保存或写入事实库；前端也不应该根据错误正文推断下一步业务动作。

## 调整思路

新增独立的 `terminal failure finalizer` 阶段：主 Agent 已经失败后，production chat adapter 先按 runtime / validator / budget / provider facts 做确定性分类。如果失败属于可分类内部合同失败，且 provider availability gate 证明模型仍可调用，则额外调用一次受限 LLM，只生成失败解释和最多 3 条 `suggestedQuestions`。

finalizer 不进入主 Agent repair loop，不接收 tool manifest，不输出 `AgentAction`、`tool_call`、`visibleOutputs` 或 NDJSON，也不能声称已完成、已保存或已执行未发生的业务结果。provider quota、rate limit、auth、HTTP、network、timeout 或配置缺失时不会调用 finalizer，直接走确定性安全 fallback。

## 关键改动

- 在 `lib/server/config/` 集中新增 finalizer 行为预算和独立 prompt 配置。
- 新增 `lib/server/chat/terminal-failure-finalizer.ts`，定义脱敏 input builder、provider gate、独立 output schema、DeepSeek finalizer adapter 和输出安全校验。
- `/api/chat` production adapter 增加异步失败投影：finalizer 成功输出 `content` / `suggested_questions` / `done`，失败或不可用时保留确定性 fallback。
- trace 记录 finalizer gate、promptVersion、模型请求/响应摘要、token usage、输出校验、skip/degrade reason 和最终 `projectionType`。
- 手动 LLM 报告新增响应来源诊断，区分 `main_agent_completed`、`terminal_failure_finalizer`、`deterministic_fallback` 和 `provider_unavailable`。

## 取舍

这个方案比“前端看到 error 后显示一段友好文案”更可维护，因为失败分类、provider gate、trace 和输出 schema 都在服务端生产边界内完成；前端只消费标准 NDJSON 事件，不解释内部错误。

它也比“再给主 Agent 一次 repair”更安全，因为 finalizer 不具备 tool calling 能力，不能继续尝试生成训练卡片或保存事实，只能解释本轮未完成并给出下一轮建议。
