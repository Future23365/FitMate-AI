## 问题

`replace-chat-orchestrator-with-tool-first-agent` 已完成 Agent 契约和工具注册，但还缺少可测试的运行时闭环。没有 `runAgentOrchestrator`、依赖图、checkpoint、Response Writer 投影和 Agent prompt/token 观测合同时，后续直接切换 `/api/chat` 容易把旧 intent-first 分支包装成新的大函数，也无法证明最终回复来自真实 tool result。

## 调整思路

本阶段只落地 Phase 4 能力，不切换 `/api/chat` 生产入口。新增独立 Agent runtime，让模型决策、工具执行、tool result 登记、dependency graph、checkpoint/replay 和 final result 先在测试中闭环；Response Writer 只消费 `AgentExecutionResult` 投影，不重新解释语义或承诺未执行写入。

## 关键改动

- 新增 `lib/server/agent-orchestrator/runtime.ts`，提供 `runAgentOrchestrator`、checkpoint 和 replay fixture。
- 新增 `lib/server/agent-orchestrator/response-writer.ts`，支持 `answered`、`generated`、`patched`、`completed_operation`、`blocked`、`failed` 的安全投影。
- 扩展 AI trace step 类型和 `/dev/ai-traces` 分组，支持 Agent context、tool decision、tool result 和 final result。
- 扩展 token budget 和 prompt registry，新增 `agent_context_build`、`agent_tool_decision`、`agent_tool_execution`、`agent_final_result`、`agent_response_writer`、`agent_summary_update`。
- 更新下游模型提示词描述，使 Agent 主链输入改为结构化 intent/edit plan、candidateSetId、ContextPackage 摘要或 tool result，不再声明只依赖 `conversationSummary + latestUserMessage`。
