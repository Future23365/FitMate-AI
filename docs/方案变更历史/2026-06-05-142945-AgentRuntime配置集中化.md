# Agent Runtime 配置集中化

时间：2026-06-05 14:29:45 CST

## 原问题

生产 Agent 的关键行为预算分散在多个模块：prompt 默认请求参数在 prompt config，DeepSeek timeout 和 trace 长度在 adapter，`/api/chat` run limits 在聊天服务，tool timeout、动作返回数量和最近事实数量散落在 tool、repository 和 fact store。排查 `max_tokens`、repair、timeout 或 tool 返回数量时需要跨文件追踪，也容易在后续修改中出现生产、测试和本地行为漂移。

## 调整思路

新增 `lib/server/config/` 作为服务端 Agent 配置边界，把 provider 无关的行为预算集中成 TypeScript 配置，并继续保留 `DEEPSEEK_API_KEY`、`DEEPSEEK_API_URL`、`DEEPSEEK_MODEL` 的环境变量部署边界。配置按 `llm`、`runtime`、`tools`、`trace` 分组，所有公开配置项补充中文意图注释。

## 关键改动

- 将生产 Agent LLM prompt 配置迁移到 `lib/server/config/agent-llm-prompt-config.ts`，保持 prompt 语义、`agentLlmPromptVersion` 和测试注入能力不变。
- 新增 `lib/server/config/agent-runtime-config.ts`，集中管理 LLM 默认请求参数、Agent run limits、tool 可见事实数量和模型 trace 长文本裁剪。
- `DeepSeekModelAdapter`、`agent-text-chat-service`、`searchExerciseResources`、`resolveExerciseResourceMentions`、`inspectVisibleTrainingProposals` 改为读取集中配置。
- repository 和 fact store 保留 hard cap，避免未来误调导致模型上下文或历史事实读取失控。
- 更新 prompt 指南和 architecture boundary 测试，明确当前入口位于 `lib/server/config/`。

## 边界

本次没有新增业务 tool，没有修改 `/api/chat` 请求/响应契约，没有新增服务端自然语言关键词分流，也没有把 runtime budget 下放到新的环境变量。
