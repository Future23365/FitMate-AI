# 聊天卡片事实源

## 当前问题

聊天已经能推送动作推荐、单次 routine 和长期 plan 卡片，但这些结构化结果主要保存在消息 metadata 和前端局部状态里。用户后续说“这个”“上一套”“刚才那批动作”时，服务端只有自然语言 `conversationSummary` 和旧消息 metadata，缺少稳定、可检索、可修订的事实对象。

如果继续从 `conversationSummary` 反推训练内容，会把自然语言摘要当成结构化事实源，容易丢失动作参数、训练日、三段式 section 和循环配置。

## 调整思路

新增 `ConversationArtifact` 表保存用户在聊天中实际看过的结构化卡片，新增 `ArtifactIndex` 保存轻量检索字段。完整 payload 仍按 `kind` 和 `payloadSchemaVersion` 走服务端 Zod 校验，引用解析和聊天上下文只读取 index summary，不扫描大 JSON。

聊天历史保存时会为消息上的 `exerciseRecommendation`、`routine` 和 `plan` 创建 artifact。相同消息 payload 未变化时保持幂等；payload 变化时创建新 revision，并把旧 artifact 标记为 `superseded`。

## 实现方式

- Prisma 新增 `ConversationArtifact`、`ArtifactIndex` 及相关 enum。
- 新增 Artifact Service，统一处理 payload 校验、索引生成、recent summaries、来源实体回写和 revision。
- `/api/chat` 请求增加 `conversationId`，模型上下文可获得当前会话最近 active artifact summaries。
- 聊天保存 routine 或导入 plan 时，通过 `sourceChatMessageId` 将 artifact 关联到保存后的 `WorkoutRoutine` 或 `WorkoutSchedule`。
- `conversationSummary` 继续只作为自然语言摘要，不再承担恢复完整训练 payload 的职责。

## 结果

聊天卡片从临时展示 payload 升级为服务端可引用事实源，为后续引用解析、训练修改和 trace 复盘提供稳定基础。相关测试覆盖 artifact 创建、索引、权限过滤、revision、聊天卡片保存和旧请求无 artifact 兜底。
