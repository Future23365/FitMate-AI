# 2026-05-31 统一 AI 建议协议

## 背景

聊天建议曾分散在 `suggestedReplies`、`clarificationReplies`、`adjustmentReplies`、artifact 失败恢复建议和 patch 确认建议中。前端需要理解多套字段，AI Trace 也难以判断某个按钮来自哪一层；同时模型偶尔会返回“请重新说明你的训练目标、时间和器械条件”这类助手对用户说话的文本，不适合作为用户点击后发送的消息。

## 调整思路

本次把用户可见建议收敛为统一的 `assistantSuggestions`。各 LLM 阶段仍在自己最了解语义的地方产出建议候选，不新增默认 suggestion 专用模型调用；服务端只负责统一结构、来源标记、用户口吻校验、去重、阻断优先级和 trace 诊断。

## 关键改动

- 新增共享 `AssistantSuggestion` 协议：`label` 负责展示，`message` 负责点击后发送，`kind` 和 `source` 记录业务语义。
- `/api/chat` 在流中优先输出 `assistant_suggestions`，并继续输出 `suggested_replies` 兼容旧客户端。
- 服务端统一归一化旧字段、意图阶段建议、动作推荐下一步建议、artifact 失败恢复、引用确认和 patch 确认。
- 前端消息气泡优先渲染 `assistantSuggestions`，点击按钮发送 `message` 而不是 `label`。
- AI Trace 增加统一建议归一化步骤，记录原始来源、过滤原因和最终可见建议。

## 结果

建议按钮从多字段分散模型收敛到单一协议，旧字段仍作为兼容输入保留。典型非法口吻建议会在服务端被过滤并进入 trace，动作推荐成功后可以返回 `next_action` 类型建议，引导用户继续生成训练或调整推荐。
