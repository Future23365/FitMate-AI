# 2026-06-05 21:07:10 CST Agent 同义语义槽字段收敛

## 背景

生产 Agent 合同里存在多组同义字段分裂：终态文本在 `final_answer.content` 和 `ask_user.question` 之间切换，terminal grounding 在 `usedToolResultIds` 和 `usedResourceRefs` 之间切换，`inspectVisibleTrainingProposals(read_recent)` 同时暴露顶层 `factRef` / `messageId`，`searchExerciseResources` 同时暴露 `muscle` / `muscles`。这些字段表达的是同一类语义槽，却要求模型根据 action、引用类型或单复数切换字段名。

## 原方案为什么不合适

继续依赖 prompt 强调旧字段差异，只能缓解单个失败 case，不能降低模型在长 prompt、长 manifest 和 repair 循环中的字段记忆负担。服务端如果静默把旧字段转换成新字段，也会把旧字段变成事实兼容合同，后续模型仍可能继续输出旧形状。

## 调整思路

本次采用统一语义槽字段的方式：字段名只表达数据槽本身，语义差异由 `type`、`operation` 或 `ref.type` 这类判别字段表达。服务端仍只做结构、权限、resource、tool result 和数据库事实校验，不根据用户原文新增关键词、正则、同义词或短句模板分流。

## 关键改动

- `final_answer` 和 `ask_user` 统一使用 `content` 承载用户可见文本。
- terminal grounding 统一为 `usedRefs`，通过 `type = "tool_result" | "resource"` 区分来源。
- `inspectVisibleTrainingProposals(read_recent)` 统一使用 `ref: { type, value }` 读取可见训练方案事实；`factRef` / `messageId` 继续作为事实索引值存在，不再作为顶层输入槽。
- `searchExerciseResources` 只保留 `muscles` 数组；单肌群也用单项数组。
- 默认 Agent prompt、tool manifest、schema description、examples、repair feedback、observation、trace 和 replay fixture 同步到新合同。
- `visibleTrainingProposal` 终态校验从具体 `toolName` allowlist 解耦为读取 satisfied tool result 的 `projection.model.groups` 事实形状。
