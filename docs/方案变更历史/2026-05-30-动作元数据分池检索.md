# 动作元数据分池检索

## 当前问题

训练草稿生成和局部 Patch 过去主要依赖动作相关性、肌群、器械和基础难度筛选。这个方式能找到“看起来相关”的动作，但不能稳定判断动作是否适合放进热身、主训练或拉伸阶段，也缺少替代、降阶、进阶关系的明确依据。

典型风险是：主训练动作可能被模型放进热身，拉伸动作可能进入主训练；用户要求“换简单点”时，系统只能按同肌群兜底，无法优先使用动作库里更明确的降阶关系。

## 调整思路

这次把动作库升级为更明确的候选事实源。`Exercise` 增加训练阶段、动作角色、运动模式、难度、禁忌、降阶/进阶和替代分组等元数据；服务端读取动作时统一归一化，历史 seed 缺字段时使用保守默认。

候选服务不再只返回一组相关动作，而是额外输出 `warmup`、`training`、`stretch`、`regression`、`progression` 和 `substitution` 分池。AI 生成 routine/plan 时收到分池候选，Validator 保存或展示前再次校验动作是否属于本次候选集合、是否允许进入对应 section。

## 怎么做

- 扩展 Prisma `Exercise` 字段和 seed 归一化逻辑。
- 新增共享动作元数据 Schema 与 `normalizeExerciseMetadata`。
- `selectExerciseCandidates` 保留原有 primary/supplementary 输出，同时新增 `candidatePools` 和结构化 `shortages`。
- routine、plan 和 Patch 校验使用动作元数据拒绝非法 section、候选外动作和不合规替代。
- Patch 替代排序优先考虑 `substitutionGroupId`、显式降阶/进阶关系、运动模式、主肌群、器械、难度和 section。

## 结果

相关单元测试已覆盖分池候选、候选不足、替代排序、候选外动作和非法 section 拒绝。后续可以继续把动作库的人工审核流程接到这些元数据字段上，减少依赖启发式默认值。
