# 基础 LLM 黑盒冒烟口径调整

时间：2026-06-06 17:57:08 CST

## 原问题

`npm run test:llm:basic` 原本会在真实首页聊天链路之后，再调用一个独立 judge 模型，根据 `llm基础测试.md` 的语义期望判定每轮是否通过。这让基础套件承担了两类职责：一类是确认 `/api/chat` 真实链路能否给用户返回内容，另一类是评估训练推荐、routine、plan 等语义质量。

随着 Agent 主链增加模型失败解释、terminal failure finalizer 和服务端确定性兜底，基础套件继续做严格语义判分会把“用户已有可见回答”的可恢复结果判成失败，也会额外消耗 judge token，增加手动冒烟测试的噪音。

## 调整思路

基础套件收敛为链路可用性冒烟测试：只要请求正常结束、收到 `done`、会话保存成功，并且最终存在任一用户可见回答面，就算通过。用户可见回答面包括 assistant 文本、可见训练输出、建议提问、确认请求和安全兜底文案。

`llm基础测试.md` 的期望列继续保留，但只作为报告中的人工复核上下文，不再由基础命令自动语义判失败。真正需要验证语义质量的场景，应转到 detailed suite 或专项回归。

## 关键改动

- 移除基础 runner 对独立 judge 模型的配置、调用和 token 统计。
- 新增 `summarizeBasicVisibleAnswer` 作为基础套件唯一通过判定。
- 报告摘要改为展示“收到 done 且存在用户可见回答”的验收口径。
- 文档同步说明 `DEEPSEEK_API_KEY` 缺失时不会使用 mock；如果生产 `/api/chat` 返回安全兜底且正常结束，基础冒烟仍通过。

## 验证方式

- 普通自动化测试覆盖可见回答判定、NDJSON 解析、报告脱敏和默认测试隔离。
- `npm run test:llm:basic` 仍是手动真实链路入口；本次不伪造最新真实模型报告，下一次手动执行会按新格式生成报告。
