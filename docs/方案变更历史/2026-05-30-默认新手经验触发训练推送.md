# 默认新手经验触发训练推送

## 调整原因

用户在已有增肌目标、训练时长、每周频率并补充“没有器械”后，系统仍因为没有明确训练经验而阻断计划推送。自然语言回复说会整理计划，但内部动作没有触发，造成对话承诺和实际结果不一致。

## 调整结果

聊天触发门控现在把缺失经验视为可由 `beginner` / 简单训练策略满足。用户没有明确经验时，系统默认推送简单、新手友好的动作推荐、单次编排或长期计划；同时继续保留动作候选不足、目标缺失、时长缺失等核心条件阻断。

回复生成也增加了内部动作状态约束：只有服务端已经触发内部动作时，模型才可以说会按当前条件整理结果；如果没有触发，则必须追问真正阻断的信息。

随后根据最新日志追加了 LLM 提示词约束：意图解析必须把 `conversationSummary` 中仍然有效的器械或场地事实合并进 `workoutIntent`；如果摘要或当前消息已经表达在家、自重、徒手、无器械或没有可用设备，模型应将其归一成可生成的结构化训练条件，而不是再次把 `equipmentOrLocation` 标为缺失。这个调整保持 LLM 负责自然语言语义理解，后端不新增中文同义词死判定。

## 解决的问题

- 避免用户只缺少经验字段时无法收到计划推送。
- 避免把默认 `beginner` 写成用户明确确认过的经验事实。
- 避免“回复说会生成，但内部没有推送”的状态不一致。
- 避免当前消息只补充经验等单一字段时，LLM 丢失摘要中已有的无器械/居家训练条件。
