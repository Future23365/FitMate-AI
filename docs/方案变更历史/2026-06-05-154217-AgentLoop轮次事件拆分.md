# Agent Loop 轮次事件拆分

时间：2026-06-05 15:42:17 CST

## 当前真实问题

首页聊天活动条曾把 `agent_progress` 事件数量当成 `#N` 轮次。这个方案把“后端真实 Agent Loop 轮次”和“当前可展示活动阶段”混在一起：同一轮内的 planner、validation、tool execution、finalizing 或 content 阶段都会让前端误以为进入了新一轮。

结果是 UI 可能出现 `#N` 虚高，或者在同一轮内因为通用阶段和具体阶段切换造成“回退到正在思考”的错觉。

## 调整思路

将 stream 合同拆成两个独立事件族：

- `agent_loop`：只表示当前请求内后端 `agent-core` runtime 进入第几次真实 loop。
- `agent_progress`：只表示右侧中文活动文案的阶段来源。

前端对应拆成 `loopTurn` 与 `activityStage` 两个临时 UI 状态。`sequence` 只用于顺序保护，不再用于推断 `#N`。

## 关键改动

- 在 `AgentTraceEvent` 和 `AgentStreamEvent` 中新增 `agent_loop`，payload 只包含 `loopTurn` 和 `sequence`。
- 在 `runAgentRuntime()` 的真实 loop 边界记录 `agent_loop` trace，由 `/api/chat` production stream writer 投影为安全 NDJSON 事件。
- 保留 `agent_progress` 作为 Activity 文案来源，不向其中塞入 loop 轮次。
- 前端 parser 新增 `agent_loop` 校验，并继续剔除额外内部字段。
- `VisibleAgentActivity` 改为显式保存 `loopTurn` 和 `activityStage`，删除旧 `activityRound` 本地计数。
- `AgentActivityIndicator` 只有收到合法后端 loop 事件后才展示 `#N`。
- 增加测试覆盖同一 loop 多 Activity、新 loop 重复相同文案、content 不递增 loop、无 loop 前缀和 payload 安全边界。
