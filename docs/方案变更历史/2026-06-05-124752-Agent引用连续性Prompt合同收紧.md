# Agent 引用连续性 Prompt 合同收紧

时间：2026-06-05 12:47:52 +0800

## 背景问题

`codex_logs/ai_trace_log.js` 中的“文本聊天：换一批”显示：Planner 第一轮调用了 `inspectVisibleTrainingProposals(operation = "list_recent")`，第二轮已经看到 `facts=[]` 的 observation，但最终仍复读历史 assistant 能力介绍。这说明问题不在 runtime 校验或 tool handler，而在模型可见合同没有足够强调“本轮用户请求”和“本轮最新 observation”应优先参与引用对象推理。

## 原方案为什么不合适

直接在 `/api/chat`、runtime 或 handler 中按用户短语、`factCount = 0` 或固定 `toolName` 分支处理，会把自然语言理解从模型挪到服务端，破坏“模型能力优先，服务端只管契约”的边界。强制所有 terminal action 引用本轮 tool result 也过重，会影响普通问答和不需要 tool 的回复。

## 调整思路

本次只收紧模型实际可见输入：

- `agentLlmPromptVersion` 升级到 `agent-action-v8`，便于 trace 区分新旧 prompt。
- 通用 Agent prompt 增加引用对象连续性规则：省略、续问、替换、调整、继续或引用最近内容时，模型基于 `run.messages`、`metadata`、`observations` 和 `toolResults` 自主判断引用对象是否存在且可操作。
- prompt 明确历史 assistant 消息只能作为上下文参考，不能作为本轮回复模板复读，除非用户明确要求复述。
- `inspectVisibleTrainingProposals(list_recent)` 的 model projection 补充 `facts[]` 事实边界：空数组只表示当前可见事实中没有这类引用对象，可支持解释或澄清，不能支撑成功刷新或新训练方案生成。

## 关键边界

- 不新增 `/api/chat`、Agent runtime、validator、tool handler 或 renderer 的自然语言短语分流。
- 不把 `换一批`、`再来一组`、`factCount = 0` 写成生产触发条件。
- 不强制模型固定调用某个 tool、固定输出某个 `payload.kind`，或固定引用某个 tool result/resource。
- 业务名 `visibleTrainingProposal` 只作为 tool/projection/resource/test 事实合同出现，不作为通用语义触发规则。
