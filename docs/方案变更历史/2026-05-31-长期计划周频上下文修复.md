# 长期计划周频上下文修复

## 真实问题

最新 `docs/manual-llm-blackbox-flow-latest-report.md` 只剩 `F05` 第 3 轮失败。用户已经按长期计划流程逐步补齐：

1. `给我一个每周训练计划`
2. `每周4练，每次45分钟`
3. `增肌，有健身房器械`

系统应生成 `workout_plan`，但实际触发了 `exercise_recommendation`。这说明服务端在第 3 轮没有稳定识别“前面是在补齐长期计划”。

## 调整思路

根因在结构化会话事实抽取：`buildFitnessConversationContext()` 只识别 `每周4次`，没有识别用户更自然的 `每周4练`。黑盒 runner 每轮会用消息历史重建 `conversationContext`，因此第 2 轮的周频事实没有进入 `knownFacts.weeklyFrequency`，第 3 轮被纯目标推荐规则抢先归一化。

这次选择修事实抽取，而不是给 `增肌，有健身房器械` 加特殊分支。因为这句话单独出现时不一定是长期计划；只有历史里已有 plan cadence，才应该进入 plan completion。

## 关键改动

- `extractWeeklyFrequency()` 支持 `每周N练`、`一周N练`、`N练/周` 等周频表达。
- `tests/chat-service.test.ts` 使用真实消息历史构造 `buildFitnessConversationContext()`，验证 `每周4练，每次45分钟` 会抽取 `weeklyFrequency=4` 和 `sessionMinutes=45`。
- 同一测试验证后续 `增肌，有健身房器械` 会归一化为 `workout_plan`，并触发 `workout_plan` action，而不是动作推荐。

## 验证

- `npm run test -- tests/chat-service.test.ts`
- `npm run typecheck`
- `openspec validate fix-weekly-plan-completion-context --strict`

真实 `npm run test:llm` 会消耗外部模型 token，本次不主动运行，等待用户确认成本后再刷新最新黑盒报告。
