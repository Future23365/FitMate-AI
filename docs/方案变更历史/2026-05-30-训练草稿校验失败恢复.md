# 训练草稿校验失败恢复

## 当前问题

聊天推送训练计划时，`/api/ai/workout-plan` 会在草稿生成后执行服务端校验。此前所有校验失败都会直接变成终止型“计划生成失败”，例如 `session_too_long` 会让用户看到失败卡片，但用户无法在当前对话里选择压缩时长或保留完整训练量。

这类问题并不是权限、动作 ID 或数据污染问题，而是训练方案需要调整。如果直接终止，会让可修复的生成偏差变成不可继续的用户体验。

## 调整思路

保留服务端校验作为最终边界，把失败分为可恢复问题和硬边界问题。可恢复问题先交给 LLM 自动修复一次；修复后仍失败时，接口返回结构化引导，前端展示可继续对话的建议回复。

硬边界问题仍不能展示或保存失败草稿，避免无效动作、候选外动作或错误结构进入训练卡片。

## 方案

- 新增训练草稿校验失败分类工具，统一生成 `recoverable`、`guidanceMessage` 和 `suggestedReplies`。
- `/api/ai/workout-plan` 首次校验失败后发起一次修复请求，把原始草稿、校验结果、用户 intent 和候选动作交给模型。
- 修复后的草稿重新走同一套 Schema、候选动作和训练规则校验。
- 修复通过时返回修复后的有效草稿；修复失败时返回结构化失败结果，前端只展示引导，不展示失败草稿。
- 前端 silent generation 保留恢复错误的结构化信息，并在聊天气泡内提供继续对话建议。

## 结果

`session_too_long` 这类训练时长超出问题从“直接终止”调整为“自动修复一次，失败后引导用户选择”。训练卡片仍只展示通过服务端校验的草稿。
