# 项目演变历程

## 2026-05-30 训练草稿校验失败恢复

为解决聊天推送训练计划时 `session_too_long` 等可调整校验失败直接终止的问题，训练草稿生成链路增加了一次服务端自动修复。修复结果仍重新通过 Schema、候选动作和训练规则校验；如果修复失败，前端展示可继续对话的引导和建议回复，不展示未通过校验的训练卡片。

## 2026-05-30 聊天卡片事实源

为解决用户后续引用“这个”“上一个”“刚才那套”时缺少结构化事实源的问题，聊天推送的动作推荐、routine 和 plan 卡片新增 `ConversationArtifact` 持久化层。模型上下文读取 recent artifact summaries，而 `conversationSummary` 继续只保存自然语言摘要；保存 routine 或导入 plan 后会把 artifact 关联到对应来源实体。

## 2026-05-30 聊天引用解析

为解决用户用“这个”“刚才那套”“之前那套练胸的”引用历史训练内容时模型容易猜错对象的问题，聊天链路新增 `ReferenceResolver`。引用解析在服务端基于 recent artifact summaries 和 `ArtifactIndex` 候选集合完成；歧义和未找到时直接返回澄清，不再从 `conversationSummary` 伪造历史卡片。

## 2026-05-30 训练内容局部 Patch

为解决用户只想替换或降低某个动作难度时系统容易重生成整份训练的问题，聊天链路新增 `WorkoutPatch` 和 PatchEngine。ReferenceResolver 已定位 artifact 后，服务端只对被点名动作应用 `artifact_only` 局部修改，替代动作必须来自动作候选集合；成功结果创建新的 artifact revision，saved routine、future schedule 和 completed history 默认 blocked。

## 2026-05-30 AI 编排基础 Trace

为解决 Artifact、ReferenceResolver 和 Patch 接入后错误来源难以复盘的问题，AI trace 从模型调用日志扩展为基础 `AiRunTrace`。现在 `/api/chat` 会记录用户、会话、模型、prompt/tool 版本、recent artifact 摘要和最终决策，并按阶段展示引用解析、受控工具调用、Patch、校验、持久化和响应写入结果；敏感字段和长 payload 会在 trace 层脱敏或截断。

## 2026-05-30 动作元数据分池检索

为解决动作相关性召回无法稳定区分热身、主训练、拉伸和替代关系的问题，动作库新增阶段、角色、运动模式、难度、禁忌和替代关系元数据。候选服务会输出 warmup、training、stretch、regression、progression 和 substitution 分池；routine、plan 和 Patch 保存前再次校验动作必须来自本次候选集合，并且允许进入对应 section。

## 2026-05-30 长期计划领域引擎

为解决长期计划由 LLM 自由铺满日历导致周频率、恢复间隔和递进不可控的问题，聊天链路新增 `PlanStrategy + DomainPlanEngine`。当用户引用已有 routine / plan 并要求“三周都练这个”或“改成一周四练但别太累”时，服务端读取受控 artifact payload，按策略展开 schedule preview，并在返回前校验训练日数量、时长、动作来源和连续负荷。

## 2026-05-30 用户反馈结构化记忆

为解决用户反馈只停留在 `conversationSummary` 中、后续推荐和计划无法稳定复用的问题，系统新增 `UserMemory` 与 `UserExerciseFeedback`。聊天反馈会按长期偏好、动作难度、临时上下文和健康/不适信号分层写入；候选检索、Patch、Validator 和 DomainPlanEngine 读取同一份记忆状态，训练完成率和主观疲劳也会作为后续递进输入。

## 2026-05-30 RAG 混合检索

为解决“拜拜肉”“核心不稳”“圆肩”“之前那套练胸的”等模糊表达召回不足的问题，RAG 从 prompt 辅助升级为结构化硬过滤约束下的混合检索。Artifact 和 Exercise 维护安全的 `embeddingText` 与本地 embedding；ReferenceResolver 和动作候选服务先执行权限、状态、器械、section、风险等硬过滤，再做全文、向量和业务 rerank，并把 query、过滤、召回、排序与最终候选写入 AiRunTrace。

## 2026-05-30 写操作 Policy 与确认门

为解决 AI 对训练草稿、已保存 routine、未来 schedule 和长期记忆缺少统一写入边界的问题，服务端新增 `PolicyEngine` 与 `ConfirmationGate`。未保存聊天草稿的单动作修改仍可直接创建 artifact revision；覆盖 saved routine、批量 future schedule、改变频率/日历/强度、长期健康限制写入等高影响操作会先返回确认问题和 diff 摘要，确认 token 绑定 userId、目标、scope、operation 和过期时间，写入前必须重新校验。

## 2026-05-31 AI Token 预算编排

为解决多阶段 AI 编排后 token 成本来源不透明、候选动作 payload 偏宽、summary 更新默认每轮触发的问题，服务端新增 `token-budget` 决策层。聊天、动作推荐和训练计划生成现在会记录本轮 AI 阶段执行/跳过状态、prompt modules、模型可见上下文和候选裁剪摘要；动作候选传给模型前收敛为白名单字段，确认、取消、换一批等无新长期事实的短操作可以跳过 summary LLM 更新。

## 2026-05-31 移除医疗健康风险决策边界

为避免系统基于疼痛、伤病、不适或动作风险标签替用户决定能不能训练，健康/医疗信号不再参与动作候选排除、训练计划生成、Patch 替换拒绝或长期记忆确认。相关字段和历史枚举保留为兼容数据，但服务端只继续执行动作库、候选集合、结构化校验、权限隔离等非医疗边界；自然语言回复仍不得提供医疗诊断或治疗承诺。

## 2026-05-31 统一聊天意图决策流

为解决聊天回复、内部动作、前端 trigger 和训练计划接口各自解释意图的问题，聊天主链路新增 `ResolvedChatIntent` 执行契约。`/api/chat` 现在先完成 resolved intent、门控、必要 repair、artifact 生成和校验，再生成最终回复；前端只展示服务端返回的 artifact 或失败恢复，不再从正文 trigger 或 `assistant_action` 二次调用生成接口。长期计划 `PlanStrategy` 同步记录字段来源和默认假设，防止默认 21 天等兜底值覆盖用户明确周期。

## 2026-05-31 只读 LLM 工具调用

聊天模型过去只能依赖 `conversationSummary`、recent artifact 摘要和固定服务端分支回答复杂追问，无法按需补查真实 artifact 或动作库。现在新增了受控只读工具层和 `runReadonlyToolLoop`：LLM 只能通过 JSON decision 选择 `searchArtifacts`、`getArtifactPayload`、`getExerciseById`、`searchExercises` 四个读工具，服务端负责白名单、Schema、权限、预算、摘要和 trace。

该能力默认由 `ENABLE_READONLY_LLM_TOOLS` 关闭；开启后也只进入历史 artifact 解释、动作详情补查、推荐理由解释和计划理由解释，不改变生成型训练计划、routine、动作推荐或 Patch 的执行决策。AI Trace 新增 `tool_decision`，用于复盘跳过原因、额外模型调用、工具执行和上下文截断。

## 2026-05-31 训练校验确定性边界

为解决动态关节活动被静态 section 元数据误判导致 routine 生成失败的问题，训练草稿校验从“动作阶段语义硬编码”收敛为“确定性事实边界”。动作 ID、候选集合、Schema、必要结构、时长和训练量异常仍会 hard fail；`section_exercise_mismatch` 改为 trace warning，保留 AI section 与本地元数据 section 诊断信息，但不再阻止合理草稿展示或进入恢复失败提示。

## 2026-05-31 本地匿名鉴权

为解决固定 `local-demo-user` 导致不同浏览器数据混用的问题，系统新增浏览器本地匿名身份。前端在应用挂载前创建或恢复匿名 token，统一请求层自动携带凭证；服务端 Route Handler 先解析请求级 `CurrentUser`，再调用聊天、训练、动作库、AI 生成和开发 trace 服务。后续接入正式注册登录时，业务层仍只依赖已校验的用户上下文。

## 2026-05-31 本地用户重置软删除

为解决设置页重置文案和服务端行为不一致、旧 cookie 仍可能恢复旧匿名身份的问题，用户生命周期新增 `User.deletedAt`。本地用户重置现在会二次确认、清除当前浏览器 cookie，并把旧匿名用户标记为软删除；恢复会话和私有 API 当前用户解析统一把软删除用户视为未认证，旧聊天、训练、artifact 和记忆数据保留用于审计、调试和未来迁移。

## 2026-05-31 数据库时间格式标准化

为解决数据库 `TIMESTAMP(3)`、本地时间字符串和无 offset fixture 带来的跨时区歧义，所有具体时间点 `DateTime` 字段统一映射为 PostgreSQL `timestamptz` 语义。新增 forward migration 按 UTC+0 解释旧值并转换列类型，服务端 DTO、AI trace、聊天历史和训练持久化边界统一输出 ISO 8601 UTC `Z` 字符串，测试增加 schema、migration 和 fixture 扫描防线。

## 2026-05-31 训练合理性 Hard Fail 移除

为解决用户明确要求连续多天重复当前 routine 时，服务端因 `day_similarity_high`、`consecutive_load_high` 等合理性判断阻止计划卡片展示的问题，训练草稿校验边界再次收窄。`errors` 只保留动作来源、候选集合、必要结构、payload 计数和用户明确约束；训练量、恢复、重复度、section 语义和未确认历史偏好只进入 `warnings`。时长和周频率校验新增字段来源门控，默认值和 LLM 推断值不再反向造成 hard fail。

## 2026-06-01 12:10:02 CST 聊天历史服务端 Hydration

为解决真实首页请求只带最新消息时服务端 action gate 丢失结构化历史事实的问题，`/api/chat` 请求准备阶段改为按 `conversationId + current user` 读取已保存会话和 current-session artifact summaries。已保存 `messages`、`conversationContext`、`recommendationIntents` 和 recent artifact summaries 优先进入服务端 `internalConversationContext`，客户端上下文只作为 fallback；trace 同步记录 hydration source、周频、单次时长和 recent artifact kind。确定性动作讲解新增引用诊断流事件，黑盒报告可以区分 reference resolved、payload 可读和真实读取失败。

## 2026-06-01 13:09:23 移除服务端语义意图归一化

为解决“跳绳换成别的”等局部替换被服务端关键词规则改写成整套 routine 重新生成的问题，聊天主链路移除了会覆盖 LLM 高层意图的服务端语义归一化。现在 LLM 负责自然语言语义判断，服务端只保留契约校验、引用解析、权限隔离、候选来源和 patch 范围校验；fallback 只产生安全非执行结果，引用型 action 缺少 `workoutIntent` 时不再被当作生成型字段缺失。

## 2026-06-01 17:22:56 CST Agent Loop 阶段 4 运行时

为让 Tool-first Agent 在切换 `/api/chat` 前具备可测试闭环，系统新增独立 `runAgentOrchestrator` 运行时、依赖图、checkpoint/replay fixture 和 `AgentExecutionResult` Response Writer 投影。Agent prompt/token 观测合同同步迁移为 `agent_context_build`、`agent_tool_decision`、`agent_tool_execution`、`agent_final_result`、`agent_response_writer` 等阶段，trace 调试页可以分组展示 Agent context、工具决策、工具结果和最终结果。

## 2026-06-02 13:35:50 CST 旧聊天 AI 接口清理

为结束 `/api/chat` Agent-first 主链和旧聊天 AI 独立接口并存的问题，旧计划草稿 route、旧动作推荐 route、前端旧 route helper、旧 trigger JSON parser、旧 reference resolver service、旧 workout patch chat service 和旧 shared referenceResolution schema 被移除。聊天计划、routine、推荐、Patch 和建议回复现在只能来自 `AgentExecutionResult`、tool result、artifact / patch / suggestion 事件或已存在 Agent result 的确定性操作；新增架构级扫描测试防止旧执行面和旧主规格要求回流。

## 2026-06-02 14:13:19 CST Agent Artifact Revision 与 Tool Loop 稳定化

为解决用户要求“这8个动作做成一套训练”时 recent artifact summary 可见但完整 payload 因旧 revision 变成不可访问的问题，Agent artifact 读取和 artifact-bound routine 生成改用同 lineage active revision 恢复。`requiredExerciseIds` 仍必须来自恢复后的推荐 payload；runtime 同时新增重复不可重试工具失败熔断和模型可见失败摘要压缩，避免同一个 `getArtifactPayload` 失败在 tool loop 中反复消耗 token。Trace 现在记录 requested/active artifact id 和 duplicate failure 证据。

## 2026-06-02 17:43:46 CST Tool-first 工具能力合同收紧

为解决执行型 `searchExercises` 只能“搜到候选”但不能证明“满足无器械、阶段覆盖、候选来源”等硬合同的问题，Agent 工具体系新增统一 `AgentToolCapabilityContract` 和 ToolResult fulfillment。`searchExercises` 现在必须用结构化 `operation/filters/resultRequirements` 构建候选集合，并输出 `candidateSetEvidence`；routine、plan、patch、validator、policy 和保存链路只能消费当前 run 中 `satisfied=true` 的上游资源。引用解析和记忆查询也拆成 `resolveArtifactReference` 与 `queryUserMemory`，避免候选搜索或 snapshot 被误当作精确事实源。

## 2026-06-02 20:13:13 CST Agent Runtime 资源合同稳定化

为解决 partial candidate、failed/feedback 诊断、澄清工具和执行型 routine 链路在 final result 引用上边界不清的问题，Agent runtime 新增 `consumable`、`diagnostic`、`partial`、`feedback` 资源角色。写入类终止结果只能消费当前 run 的成功 producer；诊断结果只能用于 `answered`、`blocked`、`failed`、`needs_clarification` 的说明证据。`askClarification` 成功后现在稳定投影为 `needs_clarification`，`searchExercises` 未满足 section 覆盖时返回 partial 诊断并提供恢复建议，routine warmup / stretch 可用数据库无器械受控补充动作补齐，trace 和黑盒报告同步展示资源角色与防逃逸证据。
