# 本地开发指南

本文只说明当前 FitMate AI 仓库的本地开发方式。项目简介和文档入口见根目录 [README.md](../README.md)。

## 环境要求

- Node.js：建议使用 Node.js 22，与 `Dockerfile` 中的 `node:22-alpine` 保持一致。
- 包管理器：当前仓库提交了 `package-lock.json`，默认使用 `npm`。
- 数据库：本地 PostgreSQL 通过根目录 `compose.yaml` 启动。
- AI 能力：本地 AI 聊天和手动 LLM 黑盒测试需要 `DEEPSEEK_API_KEY`。

## 安装依赖

```bash
npm install
```

## 环境变量

从模板创建本地环境变量文件：

```bash
cp .env.example .env.local
```

`.env.example` 是本地配置的事实模板，当前包含：

```bash
DATABASE_URL="postgresql://fitmate:fitmate@localhost:5432/fitmate?schema=public"
DEEPSEEK_API_KEY=
DEEPSEEK_API_URL=
DEEPSEEK_MODEL=
FITMATE_LOCAL_AUTH_SECRET=
FITMATE_ADMIN_USER_IDS=
CONFIRMATION_TOKEN_SECRET=
EXERCISE_IMAGE_LOCAL_DIR=exercises_picture
EXERCISE_IMAGE_PUBLIC_BASE_URL=/api/exercise-images
ENABLE_AI_TRACE_LOG=
```

关键变量说明：

- `DATABASE_URL`：PostgreSQL 连接串；本地 `compose.yaml` 默认账号、密码和数据库名都是 `fitmate`。
- `DEEPSEEK_API_KEY`：生产 `/api/chat` 和手动 LLM 黑盒测试调用真实模型的密钥；缺少时聊天接口返回配置错误。
- `DEEPSEEK_API_URL`：可选，覆盖 DeepSeek Chat Completions endpoint。
- `DEEPSEEK_MODEL`：可选，覆盖集中配置中的默认模型。
- `FITMATE_LOCAL_AUTH_SECRET`：本地匿名 auth cookie 签名密钥；生产环境必须显式配置强随机值。
- `FITMATE_ADMIN_USER_IDS`：允许访问 `/admin` 的 userId 列表，使用逗号或空白分隔；未配置时后台默认拒绝。
- `CONFIRMATION_TOKEN_SECRET`：高影响操作确认 token 签名密钥；生产环境应显式配置强随机值。
- `EXERCISE_IMAGE_LOCAL_DIR`：动作图片本地目录，支持相对项目根目录或绝对路径。
- `EXERCISE_IMAGE_PUBLIC_BASE_URL`：前端访问动作图片的基础 URL，默认走站内 `/api/exercise-images`。
- `ENABLE_AI_TRACE_LOG`：控制生产环境是否写入 AI trace；公开环境建议保持空或 `false`。

## 本地数据库

启动 PostgreSQL：

```bash
docker compose up -d postgres
```

初始化 Prisma Client、数据库表、动作 seed 和搜索 embedding：

```bash
npm run db:generate
npm run db:migrate
npm run db:seed
npm run db:backfill-execution-taxonomy -- --apply
npm run db:refresh-embeddings
```

`db:backfill-execution-taxonomy` 读取 `data/exercise-execution-taxonomy.backfill.jsonl` 中已经离线审查的动作执行条件 taxonomy 补丁，默认只更新仍保持 unknown-safe 默认值的 `Exercise` 行。该命令不调用 DeepSeek 或其他模型；不加 `--apply` 时只做 dry-run。

常用数据库容器命令：

```bash
docker compose ps
docker compose stop postgres
docker compose down
```

注意：`docker compose down` 默认不会删除 `fitmate-postgres-data` volume。如需删除本地数据库数据，需要显式处理 Docker volume。

## 启动应用

```bash
npm run dev
```

`predev` 会在终端提示 AI trace 调试台地址：

```txt
AI Trace 调试台: http://localhost:3000/dev/ai-traces
```

## 动作图片

- `exercises_picture/` 是默认动作图片目录。
- `EXERCISE_IMAGE_LOCAL_DIR` 默认值为 `exercises_picture`。
- `EXERCISE_IMAGE_PUBLIC_BASE_URL` 默认值为 `/api/exercise-images`。
- 服务端会在动作库、推荐卡和训练执行读取链路中统一派生当前可展示图片 URL。
- 如需从数据库中的原始 `Exercise.imageUrls` 下载图片，可执行：

```bash
npm run db:download-exercise-images
```

## 测试与检查

```bash
npm test
npm run typecheck
npm run lint
npm run build
npm run perf:frontend
```

命令说明：

- `npm test`：运行 Vitest 自动化测试，不调用真实模型，不消费 token。
- `npm run typecheck`：运行 TypeScript 静态类型检查。
- `npm run lint`：运行 ESLint。
- `npm run build`：验证 Next.js 构建、路由和服务端/客户端模块边界。
- `npm run perf:frontend`：在生产构建后汇总关键路由入口 JavaScript 体积和本地动作图片资源体积。

手动 LLM 黑盒测试会真实调用 `/api/chat` + LangChain 主链，并消费模型 token。默认自动化不会运行它：

```bash
npm run test:llm:basic -- --help
```

Codex Shadow LLM Probe 用于本地诊断生产模型可见合同是否足够清楚，不调用 DeepSeek，也不接入生产 `/api/chat`。使用方式见 [Codex Shadow LLM Probe 使用说明](./开发诊断/Codex%20Shadow%20LLM%20Probe%20使用说明.md)。

## 数据边界

- PostgreSQL 是运行时事实数据源。
- `data/exercises.zh.json` 只作为动作 seed 来源，不作为运行时回退数据。
- `data/exercise-execution-taxonomy.backfill.jsonl` 是 `Exercise` 新增执行条件 taxonomy 字段的离线补丁数据；生产环境应通过 `npm run db:backfill-execution-taxonomy -- --apply` 写库，而不是运行时从旧字段推断。
- `prisma/schema.prisma` 中表示具体时间点的 `DateTime` 字段应使用无歧义时间语义；服务端 DTO、API 响应、AI trace 和持久化 JSON 中的新具体时间点使用 ISO 8601 UTC `Z` 字符串。
