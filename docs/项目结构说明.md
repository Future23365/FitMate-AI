# 项目结构说明

本文记录当前 FitMate AI 仓库的目录职责和分层边界。完整架构背景见 [architecture.md](./architecture.md)，AgentLoop 设计见 [agent-tool-orchestrator-design.md](./agent-tool-orchestrator-design.md)。

## 页面入口

当前 App Router 页面入口：

```txt
app/(main)/page.tsx            # 首页聊天
app/(main)/composer/page.tsx   # 动作编排
app/(main)/exercises/page.tsx  # 动作库
app/(main)/plans/page.tsx      # 训练计划
app/(main)/settings/page.tsx   # 设置
app/training/page.tsx          # 训练执行
app/admin/page.tsx             # 只读后台
app/dev/ai-traces/page.tsx     # AI trace 调试台
```

`app/(main)/layout.tsx` 是主应用 shell，负责常规应用页面的侧栏和 route transition。`app/layout.tsx` 是全站根布局。

Route Handler 只负责 HTTP 入参/出参、鉴权和服务层调用，不承载复杂业务逻辑。

## 前端功能模块

```txt
features/chat/           # 聊天页面、流式读取、历史会话、训练方案卡片适配
features/exercises/      # 动作库页面、动作详情、动作图片展示
features/workouts/       # 动作编排、训练计划、训练执行、语音播报
features/workout-plans/  # 训练草稿到 routine 的转换和日程派生
```

前端功能模块可以引用：

- `components/ui/*`
- `components/app/*`
- `lib/client/*`
- `lib/shared/*`

前端功能模块不应引用 `lib/server/*`。

## 通用组件

```txt
components/ui/    # shadcn/ui 风格基础组件
components/app/   # 跨功能复用的应用级 UI，如侧边栏、Logo、图标
components/auth/  # 鉴权相关 UI
components/dev/   # 开发和调试页面组件
```

页面级组件优先放在对应 `features/*/components` 中；只有跨功能复用的 UI 才放入 `components/*`。

## 服务端代码

```txt
lib/server/agent-core/                  # Agent runtime、tool registry、validator、resource store、response renderer
lib/server/agent-planners/              # LLM planner 与 DeepSeek model adapter
lib/server/agent-tools/                 # 生产 Agent tool 白名单和 fixture tool 定义
lib/server/auth/                        # 本地匿名 auth cookie 与当前用户恢复
lib/server/chat/                        # 聊天请求归一化、历史 hydration、agent-core 文本流接入
lib/server/config/                      # Agent runtime、LLM prompt、可见输出合同等集中配置
lib/server/db/                          # Prisma Client 单例和数据库配置入口
lib/server/exercises/                   # 服务端动作库查询服务
lib/server/exercise-images/             # 动作图片本地路径解析和公开 URL 派生
lib/server/visible-training-proposals/  # 可见训练方案校验、渲染和跨 run 事实保存
lib/server/workouts/                    # 训练 routine、schedule、session result 持久化服务
lib/server/admin/                       # 后台查询服务投影
lib/server/usage/                       # 生产 AI token usage summary 写入入口
```

`lib/server/*` 是服务端专用代码，可以引用 `lib/shared/*`，不应引用 `lib/client/*`。

## 共享代码

```txt
lib/shared/chat/
lib/shared/conversation-artifacts/
lib/shared/exercise-recommendations/
lib/shared/exercises/
lib/shared/policy-confirmation/
lib/shared/search/
lib/shared/time/
lib/shared/user-feedback-memory/
lib/shared/workout-patches/
lib/shared/workout-plans/
```

`lib/shared/*` 只放前后端都可安全使用的类型、Schema 和纯函数，不放数据库、环境变量、外部 API 密钥或浏览器状态。

## 数据与资源

```txt
prisma/schema.prisma      # PostgreSQL/Prisma 数据模型

data/exercises.zh.json    # 中文动作 seed 数据
```

## Agent 生产聊天边界

生产聊天入口是：

```txt
app/api/chat/route.ts
  -> lib/server/chat/chat-service.ts
  -> lib/server/chat/agent-text-chat-service.ts
  -> lib/server/agent-core/*
```

当前生产 tool registry 由 `lib/server/agent-tools/index.ts` 创建，只注册低风险只读业务 tool：

```txt
inspectVisibleTrainingProposals
resolveExerciseResourceMentions
searchExerciseResources
```

fixture tool、写入型 tool 和训练执行 tool 不进入生产聊天主链。

## 分层约定

- `app/api/*` 不直接堆业务逻辑，复杂流程下沉到 `lib/server/*`。
- `features/*` 承载前端功能模块，不跨层读取数据库或 AI 服务。
- `lib/server/*` 承载服务端业务、AI 编排、数据库访问和外部服务调用。
- `lib/shared/*` 只承载类型、Schema 和纯函数。
- 运行时配置、模型参数、默认开关、限额和超时时间优先放入 `lib/server/config/*`。
- 生产持久化事实以 PostgreSQL 为准；AI 输出保存或执行前必须通过服务端校验。
