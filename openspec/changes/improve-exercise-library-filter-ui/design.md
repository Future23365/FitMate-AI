## Context

动作库页面已经支持 `category`、`level`、`force`、`mechanic`、`equipment`、`muscle`、`goalTag`、`riskTag`、`homeRequirement`、`published`、`sort`、`pageSize` 等查询能力，并通过 facets 返回可用选项。当前问题集中在 UI 信息架构：所有筛选几乎都是下拉框，肌群单独外露但和下方筛选割裂，排序和每页数量也混在筛选流中。

## Goals / Non-Goals

**Goals:**

- 让高频筛选维度在页面上直接可点，减少打开下拉框的操作成本。
- 让低频筛选保持可访问，但不占据主要视觉空间。
- 让已选筛选条件可见、可单项移除、可一次清空。
- 将排序和每页数量放到结果工具栏，避免和筛选语义混淆。
- 保持现有 API 查询参数和数据加载逻辑不变。

**Non-Goals:**

- 不新增筛选维度或修改筛选算法。
- 不调整 `/api/exercises` 契约、分页语义或 facets 数据结构。
- 不改动作详情面板、动作卡片内容或训练编排页右侧动作库。

## Decisions

- 核心筛选使用统一 `ChipFilterRow` 组件，覆盖肌群、分类、器械和目标。这样能复用同一套选中态、数量展示和横向滚动行为，避免每个维度各自实现。
- 低频筛选使用 `MoreFiltersPanel` 通过按钮展开。相比把所有条件继续平铺，展开面板能保留完整能力，同时降低默认页面噪音。
- 已选条件使用结构化数组保存 `key`、`label`、`value` 和 `clear` 处理函数。相比只拼接字符串，结构化数据可以支持单项移除，并减少后续扩展成本。
- 排序和每页数量保留原生 `select`，但移动到结果栏右侧。排序/分页是列表呈现控制，不属于动作属性筛选，视觉上应和筛选区分离。

## Risks / Trade-offs

- 横向 chip 在选项很多时需要滚动才能看到全部 → 只外露 facets 的前若干个高频选项，当前值仍通过已选条件 chip 展示。
- “更多筛选”收纳后低频条件入口更深 → 按钮显示低频筛选数量，降低用户遗忘当前筛选的风险。
- 单文件组件会增加局部子组件数量 → 保持子组件只服务动作库页面，不抽到共享层，避免过早泛化。
