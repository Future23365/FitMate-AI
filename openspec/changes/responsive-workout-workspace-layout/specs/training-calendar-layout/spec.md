## MODIFIED Requirements

### Requirement: 月历作为训练日历主体
训练日历页在桌面端 SHALL 以月历作为主内容主体，减少非日历内容和固定右侧详情面板对首屏空间的占用。

#### Scenario: 用户打开训练日历页
- **WHEN** 用户在桌面端打开训练日历页
- **THEN** 系统 MUST 在主内容区域优先展示当前月份日历
- **AND** 系统 MUST 避免在月历上方常驻展示已保存计划列表
- **AND** 系统 MUST 避免在普通桌面宽度下用固定右侧详情面板持续压缩月历主体

#### Scenario: 用户在普通桌面查看月历
- **WHEN** 用户在普通桌面或缩窄窗口中打开训练日历页
- **THEN** 月历主体 MUST 保持七列日期结构可扫读
- **AND** 月历主体 MUST NOT 因右侧固定面板而低于页面定义的最小可读宽度

### Requirement: 已保存计划按需展示
训练日历页 SHALL 将已保存计划作为选中日期详情面板中的按需排期入口，而不是默认常驻内容区或顶部工具栏悬浮下拉；该日期详情面板 MUST 支持宽桌面停靠和普通桌面按需浮出。

#### Scenario: 用户查看已保存计划
- **WHEN** 用户在选中日期详情面板点击“从已保存计划添加”入口
- **THEN** 系统 MUST 在选中日期详情面板内展示可用于安排训练的已保存计划列表
- **AND** 列表 MUST 支持将某个已保存计划安排到当前选中日期
- **AND** 系统 MUST 保留进入动作编排页管理全部计划的入口
- **AND** 系统 MUST 隐藏本月统计、最近动态和快速建议等非计划选择内容

#### Scenario: 用户选择已保存计划排期
- **WHEN** 用户在已保存计划列表中选择一个计划进行安排
- **THEN** 系统 MUST 使用当前选中日期创建对应 `WorkoutSchedule`
- **AND** 系统 MUST 明确回到当前选中日期详情

#### Scenario: 用户取消选择已保存计划
- **WHEN** 用户在已保存计划列表中点击返回或关闭操作
- **THEN** 系统 MUST 回到当前选中日期详情

#### Scenario: 用户在普通桌面打开日期详情
- **WHEN** 用户在不足以常驻右侧栏的桌面视口查看某个日期详情
- **THEN** 系统 MUST 以右侧浮出面板展示选中日期详情
- **AND** 浮出面板关闭后 MUST 释放月历主体横向空间

### Requirement: 月历单元格展示紧凑摘要
训练日历页 SHALL 在月历单元格内展示当天安排摘要，并把完整详情和操作交给选中日期的详情区域或详情面板。

#### Scenario: 日期存在多个安排
- **WHEN** 某个日期存在多个训练安排
- **THEN** 月历单元格 MUST 展示至少一个可识别的安排摘要
- **AND** 月历单元格 MUST 展示剩余安排数量
- **AND** 选中该日期后详情区域 MUST 展示当天完整安排列表

## ADDED Requirements

### Requirement: 日期详情支持停靠和浮出
训练日历页 SHALL 根据桌面宽度决定选中日期详情是右侧停靠展示还是按需浮出展示。

#### Scenario: 宽桌面展示日期详情
- **WHEN** 用户在足够宽的桌面视口打开训练日历页
- **THEN** 系统 MAY 将选中日期详情作为右侧停靠面板展示
- **AND** 月历主体 MUST 仍保持可扫读宽度

#### Scenario: 普通桌面展示日期详情入口
- **WHEN** 用户在不足以常驻右侧详情面板的桌面视口打开训练日历页
- **THEN** 系统 MUST 在主内容区域提供当前选中日期详情入口
- **AND** 用户触发入口后 MUST 打开右侧浮出日期详情面板

#### Scenario: 用户选择日期
- **WHEN** 用户点击月历中的某个日期
- **THEN** 系统 MUST 更新当前选中日期
- **AND** 系统 MUST 让用户能够查看该日期完整安排
- **AND** 系统 MUST NOT 因打开详情而破坏月历选中态
