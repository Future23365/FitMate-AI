## Context

`/training` 的示范图区域目前通过 `currentItem` 和 `stepElapsedSeconds` 统一计算图片索引。休息步骤会把 `currentItem` 指向下一动作或相关动作，但 `stepElapsedSeconds` 仍来自当前休息步骤，因此带多张图的计次动作会在休息倒计时中继续轮换。

现有规格已经要求休息步骤帮助用户准备下一个训练动作，本次只收紧休息态的展示方式：休息是恢复和准备阶段，不能表现得像正在执行下一动作。

## Goals / Non-Goals

**Goals:**
- 休息步骤预览下一个动作时，动作图片保持静止，不随休息倒计时轮换。
- 示范区在休息态用“下一个动作”提示当前图片的语义。
- 保留训练动作中原有的计次轮换、计时固定尾图和暂停冻结规则。

**Non-Goals:**
- 不改变时间线结构、自动推进逻辑、语音播报或训练计时。
- 不修改动作图片数据来源或动作详情抽屉。
- 不引入新的轮播组件或浏览器端定时器。

## Decisions

1. 在训练页派生独立的示范图上下文。
   - 休息态使用 `activeRestStep.nextItem` 作为优先展示对象，其次沿用现有相关动作 fallback。
   - 原因：`WorkoutTimelineRestStep` 已经携带 `nextItem`，复用时间线语义比重新扫描列表更清晰。
   - 替代方案：直接复用 `currentItem` 并在索引计算中判断休息态。该方式改动更小，但会继续混淆“当前计时对象”和“当前示范对象”。

2. 休息态固定示范图索引为 `0`。
   - 原因：第一张图通常是动作准备或起始姿态，最适合作为“下一组动作”提示。
   - 替代方案：计时动作继续展示最后一张图。该规则适合执行中的计时动作，但休息态需要稳定预览，不应展示动作终点姿态。

3. 只改训练执行页，不改共享动作预览抽屉。
   - 原因：抽屉是用户主动打开的详情查看场景，休息态自动预览和抽屉轮播语义不同。

## Risks / Trade-offs

- [Risk] 某些动作第一张图不是最直观的准备姿势 → 仍优先保持休息态静止，后续可在动作数据层补充更明确的封面图。
- [Risk] 休息态和执行态的示范图索引规则分叉 → 通过命名清晰的派生变量集中在训练页内处理，避免散落条件判断。
