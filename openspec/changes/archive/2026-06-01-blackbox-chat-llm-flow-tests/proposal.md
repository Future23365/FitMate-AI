## Why

当前 `npm run test:llm` 主要直接调用各个 LLM prompt 分支，并断言中间 JSON、意图字段和模型调用点输出；这能发现 prompt 契约漂移，但不能代表用户在首页聊天中真实看到的结果。

根目录 `测试情况预览.md` 已经把验收目标收敛为首页聊天 3 轮黑盒流程。现在需要把手动 LLM 测试脚本调整为真实用户场景：模拟用户输入，验证最终回复和卡片推送是否能跑通，第一版先验证流程可用，不验证训练数据是否完全准确。

## What Changes

- 将专用 LLM 测试从“内部调用点一致性测试”调整为“首页聊天多轮黑盒流程测试”。
- 测试用例以 `测试情况预览.md` 的 3 轮流程为输入基础，明确哪些步骤沿用同一会话，哪些场景必须新建会话。
- 测试执行必须模拟聊天页面用户输入后的服务端可见结果，重点验证：
  - 是否返回非空、可展示的用户可见回复。
  - 是否在预期时机推送动作推荐、单次训练 routine 或长期计划 plan 卡片。
  - 是否在不应推送时保持为普通回复或追问。
- 第一版只验证流程可用，不验证动作选择、训练容量、计划准确性等细节质量。
- 每次运行结束后必须生成测试报告文档，至少包含用例验证情况、预计 token 消耗、实际 token 汇总，以及失败用例的关键排错信息。
- 保留 `npm run test:llm` 与普通 `npm run test` 隔离的原则，不把真实模型黑盒测试纳入默认测试。

## Capabilities

### New Capabilities

- `chat-blackbox-llm-flow-tests`: 覆盖首页聊天多轮黑盒 LLM 流程测试、会话策略、用户可见结果断言和运行报告。

### Modified Capabilities

- `manual-llm-consistency-tests`: 将专用手动 LLM 测试的主验收目标从内部 LLM 调用点一致性，调整为首页聊天用户可见流程黑盒验收；保留隔离运行、真实模型、token 预估和报告产物要求。

## Impact

- 影响 `manual-tests/llm/**` 中的测试 fixture、runner、断言和报告生成逻辑。
- 影响 `scripts/run-manual-llm-tests.mjs` 的用例数量、token 预估、报告摘要和失败输出。
- 可能需要新增测试用的聊天流程执行器，复用服务端 `/api/chat` 编排能力或等价的服务端入口，避免绕过真实聊天链路。
- 影响 `docs/manual-llm-consistency-latest-report.md` 或新增黑盒测试报告文档的内容结构。
- 不修改生产 API 契约、数据库结构、权限模型或页面 UI。
