## Context

`/training` 当前由 `features/workouts/components/workout-session-page.tsx` 维护 `activeStepIndex`、`remainingSeconds`、准备倒计时、暂停状态和语音播报状态。可执行步骤来自 `buildWorkoutTimeline()`，而右侧训练项目列表来自 `expandWorkoutItems()`。在循环训练中，同一个训练动作会被展开成多轮重复项，这些重复项保留相同动作 `id`；如果 UI 用 `id` 或 `findIndex()` 推断当前轮次，就会把休息步骤、下一个动作和列表高亮错误地映射到首轮动作。

本次变更需要把训练执行页的用户可见流程统一回 `buildWorkoutTimeline()` 的线性步骤顺序，同时让循环训练列表显式展示轮次，给休息步骤增加专门的跳过操作，并强化语音开启/激活提示。

## Goals / Non-Goals

**Goals:**

- 让自动推进、“下一个”、列表点击和休息跳过都按时间线顺序进入真正的下一步。
- 让训练项目列表在多轮循环时能区分第几轮，并准确高亮当前轮次的动作。
- 在休息步骤提供明确的“跳过休息”操作，避免用户用通用跳过按钮猜测行为。
- 让语音开启提示、等待激活和失败重试状态在训练中更醒目、更可操作。
- 保持训练执行页与现有浅色 MD3 风格一致。

**Non-Goals:**

- 不改变训练计划生成规则、动作选择规则、AI 编排或 Prompt。
- 不修改数据库结构、API 契约或持久化数据模型。
- 不重新设计 `/plans`、`/composer` 或共享动作详情抽屉。
- 不改变组间休息、动作间休息、循环间隙的领域语义。

## Decisions

1. 以 `buildWorkoutTimeline()` 为训练执行页的唯一流程真相源。

   训练步骤推进、完成状态、休息跳过和列表跳转都应以 `activeStepIndex` 与 `WorkoutTimelineStep` 顺序为准。`expandWorkoutItems()` 仍可用于展示动作列表，但不能单独决定当前训练位置。

   取舍：继续修补基于动作 `id` 的查找改动更小，但循环训练天然会出现重复 `id`，后续仍会在高亮、下一个动作、休息预览中反复出错。使用时间线顺序能把状态来源收敛到一个地方。

2. 为训练列表构建显式的 session list view model。

   训练页可以在组件内或共享 helper 中从 `steps` 派生列表项，包括 `itemIndex`、动作信息、所属 section、循环轮次、是否当前、是否完成、跳转目标 step index 等字段。UI 不直接在渲染阶段用 `findIndex(id)` 反查当前项。

   取舍：直接给 `WorkoutItem` 增加轮次字段会污染持久化动作结构；派生 view model 不改变数据模型，也能让 `/training` 独立表达会话中的重复动作。

3. 休息跳过使用专门的休息态操作。

   当当前步骤为 `rest` 时，主控制区域展示“跳过休息”，点击后进入 `activeStepIndex + 1` 对应步骤，并重置与新步骤相关的准备倒计时、剩余时长、示范图和语音任务。非休息步骤继续使用现有“下一个”语义。

   取舍：保留通用“跳过”按钮会让用户难以判断会跳过休息还是跳过动作。休息态专门入口更符合训练现场的即时决策。

4. 语音提示以状态化 UI 呈现，而不是只靠顶部图标颜色。

   首次静音提示、刷新后等待激活、失败重试需要使用比现有小气泡更醒目的提示块或浮层，并提供明确的操作入口；顶部音量按钮继续作为主开关。提示只表达当前真实状态，不能在浏览器未确认播放时展示为已正常播报。

   取舍：单纯放大顶部按钮实现快，但无法解释刷新后“偏好开启但需用户手势”的状态。状态化提示能同时覆盖首次开启、待激活和失败重试。

## Risks / Trade-offs

- [Risk] 派生训练列表 view model 与时间线不一致 → 只从 `steps` 派生跳转目标和状态，并用测试覆盖循环训练、多组动作和休息步骤。
- [Risk] 跳过休息后旧语音或准备倒计时回调继续影响新步骤 → 跳步时复用统一 step transition 入口，清理旧 step key、倒计时和语音任务。
- [Risk] 更醒目的语音提示遮挡训练主内容 → 采用可关闭、可响应式收敛的提示区域，桌面优先放在顶部控制区附近，移动端避免覆盖主要计时内容。
- [Risk] 改动影响当前一屏训练布局 → 保持现有信息层级和浅色 surface token，只调整必要控件与列表状态。

## Migration Plan

1. 新增或调整训练页内部 helper，基于 `steps` 生成列表展示与跳转目标。
2. 替换当前依赖重复 `id` 的当前动作、下一个动作、列表高亮和点击逻辑。
3. 为休息态增加“跳过休息”按钮，并接入统一跳步处理。
4. 调整语音提示 UI，覆盖首次提示、待激活、失败重试和正常开启状态。
5. 运行相关 TypeScript/React 检查和训练时间线测试；必要时使用 Chrome DevTools MCP 验证 `/training` 渲染、Console、Network 和交互。

回滚策略：如果训练页回归，可回退到旧的 `activeStepIndex` 推进逻辑，但不应长期恢复基于重复 `id` 的当前项推断。

## Open Questions
