## Context

`AppSidebar` 已提升到全局 `app/layout.tsx`，桌面端通过固定左栏提供全局导航、创建新对话和历史对话入口。当前侧栏根节点使用 `hidden ... lg:flex`，因此在小于 `lg` 的窄屏下完全不可见，而普通页面也只在 `lg` 以上为左栏预留空间。

该问题只涉及应用壳层的响应式导航可达性，不涉及 API、AI 编排、健身领域规则或数据持久化。

## Goals / Non-Goals

**Goals:**
- 在 `lg` 以下提供明确的移动端导航入口。
- 移动端导航抽屉复用桌面侧栏的导航、新建对话、历史对话和删除能力。
- 保持 `lg` 以上桌面固定侧边栏现有布局与视觉行为。
- 保持 `/dev` 和 `/training` 独立布局不受影响。

**Non-Goals:**
- 不重做全站信息架构。
- 不改变聊天历史数据结构、存储方式或恢复逻辑。
- 不改变各业务页面的主体布局语义。
- 不引入新的 UI 依赖。

## Decisions

1. 将侧栏主体内容抽成可复用内部组件。

   桌面固定侧栏和移动抽屉共享同一份导航渲染、历史列表和事件处理。相比复制一套移动端菜单，这能避免导航项、active state、删除历史等逻辑出现分叉。

2. 移动端入口放在 `AppSidebar` 内部统一管理。

   `AppSidebar` 已经知道当前路由和是否需要隐藏侧栏，因此移动端入口也由它控制。这样 `/dev`、`/training` 的排除逻辑只保留在一个地方，不需要每个页面额外判断。

3. 使用本地 React 状态控制移动抽屉开关。

   移动导航只影响当前页面展示，不需要 URL 状态或全局 store。导航点击、新建对话、恢复历史对话、删除当前对话时关闭抽屉，避免窄屏下操作后菜单遮挡页面。

4. 桌面和移动断点继续沿用 Tailwind 默认 `lg`。

   当前页面内容已经通过 `lg:left-[260px]`、`lg:pl-[260px]` 对齐主侧栏，因此移动导航也以 `lg` 为切换边界，保持响应式规则一致。

## Risks / Trade-offs

- 移动端固定菜单按钮可能和个别页面顶部内容重叠 → 使用左上角固定定位、白色半透明 surface 和较高 z-index，并仅在 `lg` 以下展示。
- 抽屉打开后背景仍可滚动可能影响体验 → 抽屉打开期间锁定 `body` 滚动，并提供遮罩点击和关闭按钮。
- 抽取组件可能触碰现有侧栏代码较多 → 仅在 `AppSidebar` 内部重组，不改变外部 API。
