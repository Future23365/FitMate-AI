## Context

训练日历页当前使用纵向内容流：顶部标题区、“已保存计划”横向列表、月历卡片依次排列。`main` 使用 `h-screen overflow-y-auto`，月历单元格固定最小高度，导致桌面端也需要滚动才能看完整月份。

右侧固定面板已经承担“当天计划”、状态操作、本月统计和最近动态。月历主体不需要展示过多详情，应优先保证整月可扫读，再把细节留给选中日期后的右侧面板。

## Goals / Non-Goals

**Goals:**

- 让桌面端训练日历首屏以完整月历为主体。
- 把已保存计划改为工具栏里的按需打开入口，避免默认占用纵向空间。
- 保留现有训练排期、休息日、状态更新、删除和开始训练行为。
- 复用现有 `WorkoutRoutine` / `WorkoutSchedule` 数据模型和客户端 API。

**Non-Goals:**

- 不做移动端适配。
- 不改训练数据模型、API 契约或持久化服务。
- 不改训练生成规则、AI 编排或训练执行页。
- 不重新设计右侧详情面板的信息架构。

## Decisions

1. 使用紧凑顶部工具栏替代独立标题区和常驻已保存计划区。
   - 原因：训练日历的主任务是查看月份和选择日期，保存计划只是安排训练时的素材。
   - 取舍：标题说明文案会减少，但页面意图可以通过导航标题、月份控件和按钮表达。

2. 已保存计划使用按钮下拉展示。
   - 原因：用户只有安排训练时才需要浏览已保存计划，默认收起能释放首屏高度。
   - 备选方案：把已保存计划放到右侧面板。放弃原因是右侧面板已经承载选中日期详情，混入素材列表会削弱“当天计划”的语义。

3. 月历网格用剩余高度布局，而不是依赖单元格固定最小高度。
   - 原因：月份可能有 5 或 6 周，固定 `min-height` 会让整个卡片超出视口。用 `grid-template-rows` 分配高度能让桌面端更稳定地展示完整月历。
   - 取舍：单个日期格可容纳的 badge 数量减少，因此月历只展示摘要，详情放到右侧面板。

4. 单日格展示紧凑摘要。
   - 原因：月历应该优先支持扫读日期状态，不应该承担完整训练列表。
   - 取舍：一天多条安排时不展示全部标题，只展示首条和剩余数量；用户选择日期后在右侧查看完整列表。

## Risks / Trade-offs

- [Risk] 已保存计划入口收起后不够明显 → 在顶部工具栏保留带数量的“已保存计划”按钮，并提供“管理全部”入口。
- [Risk] 月历单元格变紧凑后信息减少 → 右侧“当天计划”继续展示完整详情和操作。
- [Risk] 页面在较矮桌面视口仍可能拥挤 → 优先保证日历卡片本身不被上方内容挤压，并允许主区域在极端视口下滚动。
