## Context

`/training` 已经改为手动开始训练：刷新页面后，用户会先停留在待开始状态，点击开始按钮后才启动准备倒计时、计时和语音激活。旧的语音按钮仍保留 `needs-activation` / `failed` 重试分支，导致同一个按钮在不同状态下既可能关闭语音，也可能尝试恢复播报。

## Goals / Non-Goals

**Goals:**

- 顶部语音按钮只保留两个用户可理解的功能：打开语音、关闭语音。
- 刷新后本地语音偏好已开启时，不再提示用户重新点击语音按钮恢复播报。
- 训练开始后的语音激活继续由开始按钮负责，保证 Web Speech 用户手势链路仍然存在。
- 失败或等待激活状态不再把语音按钮渲染成重试入口；用户如需重新尝试，可先关闭再开启或使用设置弹窗自检。

**Non-Goals:**

- 不重写 `WorkoutVoiceSession` 调度器。
- 不改变语音设置、自检、voice 选择、音量/语速配置。
- 不改变训练开始、暂停、跳步、倒计时或自动推进规则。

## Decisions

1. 语音按钮点击按“偏好是否开启”分支，而不是按播放状态分支。
   - 如果语音偏好关闭：点击开启偏好，并播报固定的“语音播报已开启。”确认语。
   - 如果语音偏好开启：点击关闭偏好，取消当前语音任务并写入关闭状态。
   - 取舍：不再提供一键重试按钮，但按钮语义稳定，符合当前手动开始训练流程。

2. 保留开始按钮中的当前步骤播报激活。
   - 刷新后如果本地语音偏好仍是开启，页面不主动恢复播报；用户点击开始训练时才尝试当前步骤播报。
   - 取舍：浏览器播放权限仍然来自明确用户手势，但不会在待开始阶段额外制造恢复提示。

3. UI 状态不再把 `needs-activation` / `failed` 渲染成醒目的重试态。
   - 按钮的视觉状态只表达支持情况、偏好开启、偏好关闭和首次提示。
   - 取舍：失败诊断入口保留在设置弹窗自检中，而不是在开关按钮上承载第三种动作。

## Risks / Trade-offs

- [Risk] Web Speech 被浏览器阻止后，用户不能直接通过同一个已开启按钮重试。→ Mitigation: 点击关闭后再次开启仍可触发确认语，自检入口保留详细诊断；正式训练播报仍由开始按钮触发。
- [Risk] 内部状态仍可能是 `needs-activation` 或 `failed`。→ Mitigation: 这些状态继续用于调度器和诊断，但不改变顶部开关的两态用户语义。
