## 设计说明

本次调整把“默认基准测试”和“真实 LLM 详细黑盒测试”放在同一个 `npm run test` 命令族下，但通过显式参数隔离成本和外部依赖。

本 change 中的三种模式边界如下：

- `npm run test`：普通自动化基准测试，不请求真实模型，不读取 LLM 专用 fixture。
- `npm run test:llm`：基础 LLM 黑盒测试，面向高频 P0 冒烟流程，优先验证首页聊天主链路是否可回答、可推卡、可保持基本多轮连续性。
- `npm run test --detail`：完整/详细 LLM 黑盒测试，面向更高成本的完整回归，覆盖 `LLM完整测试.md` 中的主要能力域，但首版不承诺自动化所有文档用例和人工 UI 验收项。

设计取舍：

- `npm run test` 不带参数仍运行普通 Vitest 基准测试，避免缺少 `DEEPSEEK_API_KEY`、模型网络或 token 成本影响日常验证。
- `npm run test --detail` 通过 `scripts/run-tests.mjs` 分流到 `scripts/run-manual-llm-tests.mjs --detail`，只有用户显式要求详细模式才进入真实模型黑盒流程。
- `npm run test:llm` 继续运行基础 9 流程，兼容已有手动 LLM 验收习惯。
- `manual-tests/llm/flow-fixtures.ts` 作为测试事实源，保留 `basicBlackboxFlowCases`，新增 `detailedBlackboxFlowCases`，并通过 `getBlackboxFlowCases()` 选择套件。
- 详细套件仍只断言用户可见文本、内部字段泄漏和卡片类型；复杂语义边界先记录在 `note` 和报告里，避免真实模型措辞波动导致过多误报。
- 详细套件写入独立报告，基础报告和详细报告互不覆盖。

详细套件首版不把 `LLM完整测试.md` 的所有人工验收项都自动化。UI 输入焦点、流式展示、卡片视觉、滚动和错误提示仍属于人工或浏览器验收；本次只覆盖服务端首页聊天黑盒流程。

## 覆盖边界

基础套件用于回答“首页聊天主链路有没有断”。它覆盖动作推荐、推荐升级 routine、信息补齐、routine 调整、长期计划补齐、长期计划语义区分、历史条件覆盖、非健身切回健身和最近卡片引用。

完整/详细套件用于回答“更广的首页聊天能力是否出现明显回归”。它在基础套件之上扩展普通建议问答、寒暄、候选不足、不存在动作、多条件过滤、动作解释、短时训练、高强度请求、目标切换、局部替换、计划频率修改、日程偏好、高频训练保守处理、临时限制、同轮条件覆盖、非健身插入后的上下文恢复、引用歧义、医疗诊断边界、极端减脂和内部字段泄漏。

完整/详细套件仍不是 `LLM完整测试.md` 的逐项全量自动化。未落入首版详细 fixture 的文档用例应保留在 `LLM完整测试.md` 作为后续扩展来源；后续新增 fixture 时必须优先补高价值回归点，而不是只增加措辞相近的重复场景。

## 已知限制与后续改进

- 当前 runner 复用服务端聊天编排函数并在进程内维护会话状态，和真实首页通过 `/api/chat`、会话保存接口、数据库 artifact 索引读取的链路仍有差异。后续如果要验证引用、artifact payload 读取和跨请求持久化，应新增更贴近 HTTP/API 的 runner。
- 当前自动断言偏向 P0/P1 稳定结果，只严格检查非空回复、内部字段泄漏和卡片类型。像“第一个动作怎么做必须真的讲解成功”“不要继续使用已排除动作”“当前条件必须覆盖历史条件”这类语义质量，需要后续增加分级断言或结构化诊断字段。
- token 预估只是运行前成本提醒，不应被当作准确成本上限。后续应基于最新报告的真实 `prompt_tokens`、`completion_tokens` 和 `total_tokens` 调整预估基线。
- 详细模式报告通过并不代表所有首页 UI 行为通过；输入焦点、loading、卡片视觉、滚动和错误提示仍需要独立 UI 或浏览器验收。

## 风险与缓解

- 真实模型详细套件 token 成本显著高于基础套件。通过 `--detail` 显式触发、运行前 token 预估和独立报告降低误运行风险。
- `npm run test` 从直接 `vitest run` 改成 Node 分流器，可能影响带参数执行。分流器会把非 `--detail` 参数原样传给 Vitest，保留 `npm run test -- tests/xxx.test.ts` 的用法。
- 详细流程数量增加后，真实运行耗时更长。缺 key 时仍快速跳过并生成跳过报告，真实运行由用户明确控制。
- 基础报告和详细报告都使用“最新报告”文件名，容易被误解为长期统计。报告只代表最近一次运行；最终判断应同时看命令、套件名、生成时间、token 汇总和失败摘要。
