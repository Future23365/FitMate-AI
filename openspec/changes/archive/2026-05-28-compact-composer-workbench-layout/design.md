## Context

动作编排页已经具备保存编排、导入模板、三段式编排、右侧动作库和训练参数配置。当前问题集中在布局优先级：顶部标题区、已保存编排区和摘要指标区连续占用首屏高度，导致核心动作编排区出现得太晚。

本次采用 UI/UX skill 的高密度 dashboard/workbench 方向，但保留项目既有浅色 Material Design 3 风格和右侧动作库结构，不引入新的视觉体系、字体或大面积装饰。

## Goals / Non-Goals

**Goals:**
- 将编排名称、指标和页面级操作合并到紧凑顶部栏。
- 将已保存编排改为按钮下拉，打开后可切换、复制和删除编排。
- 让热身、训练、拉伸编排区在首屏更早出现。
- 保持移动端可换行，不让标题、指标或按钮互相遮挡。

**Non-Goals:**
- 不改变动作库筛选、添加动作、拖拽排序或预览抽屉逻辑。
- 不改变保存编排的数据结构或 API。
- 不把已保存编排移动到右侧动作库面板。
- 不启动浏览器或 dev server 做视觉验收。

## Decisions

1. 使用紧凑顶部工作台栏替代大标题区和摘要卡片。
   - 原因：当前编排名称和指标都属于当前工作对象，放在同一栏能减少重复容器并提高首屏效率。
   - 取舍：标题视觉存在感会降低，但页面会更像工具。

2. 使用按钮下拉承载已保存编排。
   - 原因：已保存编排是切换/管理入口，不是当前编辑流程的主体。
   - 取舍：切换历史编排多一步点击，但换来动作编排区默认可见面积更大。

3. 下拉仍复用 `RoutineCompositionCard` 的操作能力。
   - 原因：复制、删除、打开已有逻辑已稳定，复用可以减少行为风险。
   - 取舍：下拉中的卡片需要更紧凑，避免弹层过大。

## Risks / Trade-offs

- [Risk] 下拉在移动端宽度不足 → 使用全宽换行布局和最大高度滚动。
- [Risk] 点击已保存编排后下拉未关闭会遮挡页面 → 打开、复制、删除后关闭下拉或保留明确关闭行为。
- [Risk] lint 可能继续暴露页面既有 effect 规则问题 → 本 change 不处理无关 effect 重构，只在最终结果中说明。
