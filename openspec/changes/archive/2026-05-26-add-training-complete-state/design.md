## Context

`/training` 当前以 `activeStepIndex`、`hasStarted`、`isPaused` 和当前步骤类型驱动主展示区。`completeCurrentStep()` 到达最后一步时会调用 `finishTraining()`，后者负责重置运行状态并异步调用 `updateScheduledWorkoutStatus(plan.id, "completed")`。这个结构会把“页面已经练完了”的体验和“服务端是否记录完成”混在同一条路径里。

## Goals / Non-Goals

**Goals:**
- 为本次页面训练新增独立完成状态，表示用户已经走完当前时间线。
- 到达最后一步后，中心展示完成提示，并隐藏运行中控制和运行中文案。
- 完成展示不依赖 `updateScheduledWorkoutStatus()` 是否成功。
- 加载新训练、重新开始或页面重置时清理本地完成状态。

**Non-Goals:**
- 不修改训练时间线生成规则。
- 不修改服务端完成状态 API 或数据库记录方式。
- 不新增完成页路由、训练总结数据或持久化恢复逻辑。

## Decisions

### 使用本地完成状态表达页面会话完成

新增 `isSessionComplete` 作为页面内状态，只表示当前浏览器页面已经完成这次训练流程。到达最后一步时立即设置该状态，再异步尝试记录服务端完成状态。

取舍：不复用 `plan.status === "completed"`，因为已有规格要求打开已完成安排时仍可重新训练，且用户明确要求完成展示和服务端记录完成无关。

### 将完成流程和服务端记录解耦

保留 `finishTraining()` 负责调用 `updateScheduledWorkoutStatus()`，但让页面完成态先由本地状态决定。服务端调用失败只记录错误，不回滚完成展示。

取舍：这会让 UI 可能显示完成但服务端暂未记录成功，符合本次需求；后续如果需要补偿重试，应另行设计。

### 完成态只收敛中心运行控制

完成态隐藏中心的运行中标签、步骤计时、计次文案和“上一个/开始/下一个”等控制，同时保留页面外层导航、训练项目列表和“结束”入口等非中心运行控制的既有布局。

取舍：相比创建独立完成页面，局部收敛中心区改动更小，也能保留用户查看训练项目和返回计划页的上下文。

### 使用纯 CSS 纸屑动画表达完成反馈

完成态在中心卡片内渲染一个不可交互的纸屑层，纸屑从底部中心向上喷出并左右扩散。动画只跟随本地完成态挂载，不引入第三方依赖，也不参与训练流程状态计算。

取舍：没有引入 canvas 或动画库，是因为当前效果只服务一次性完成反馈；CSS 层更轻，也更容易受 `prefers-reduced-motion` 控制。

## Risks / Trade-offs

- [Risk] 服务端记录完成失败时，页面仍显示已完成。
  → Mitigation: 这是明确需求，错误继续通过现有日志记录，UI 不依赖服务端结果。
- [Risk] 完成态后如果用户点击训练列表跳到某一步，可能需要重新进入运行状态。
  → Mitigation: 步骤跳转时清理本地完成状态，让用户可以在当前页面重新查看或补练某一步。
- [Risk] 纸屑动画可能干扰偏好减少动态效果的用户。
  → Mitigation: 使用 `prefers-reduced-motion` 关闭纸屑动画。
