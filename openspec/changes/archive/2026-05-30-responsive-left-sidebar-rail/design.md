## Context

普通应用页面当前通过 `md:pl-[260px]`、`md:left-[260px]` 等 Tailwind class 给主内容预留左侧侧边栏空间。由于项目在 `app/globals.css` 中将 `md/xl` 等断点设为 `0px`，这些 class 在所有 PC 视口都会生效，左侧固定栏始终占用 `260px`。在聊天、训练日历、动作编排等三列页面中，右侧面板也会占用固定宽度，较窄桌面下中间区域被过度压缩。

## Goals / Non-Goals

**Goals:**

- 宽屏继续保持现有完整左侧侧边栏视觉和 `260px` 内容偏移。
- 较窄桌面下把左侧侧边栏收缩为图标 rail，并把普通页面的左侧内容偏移同步缩小。
- hover 或 focus 到 rail 时展开完整侧边栏，展开层覆盖在内容上，不改变内容区域当前宽度。
- 保持现有侧边栏数据流、导航数据、历史记录加载、设置入口和独立布局排除规则。

**Non-Goals:**

- 不重新启用手机导航或调整移动端抽屉策略。
- 不调整右侧抽屉、聊天推荐、训练计划、动作库筛选等业务逻辑。
- 不引入新的布局依赖或 JavaScript 视口监听。

## Decisions

- 使用 CSS 变量表达全局左侧占位：`--app-sidebar-offset` 在宽屏为 `260px`，在较窄桌面为 rail 宽度。这样聊天页、设置页和各工作区只依赖同一个布局事实，避免继续散落硬编码 `260px`。
- 侧边栏本体使用 CSS hover/focus-within 展开，而不是 React 状态。该交互只关心指针或键盘焦点，不需要持久化状态，也避免页面切换时出现额外状态同步。
- 收缩态保留新建、主导航、用户和设置这些可识别图标；历史列表在 rail 收缩态隐藏，展开后恢复。历史项本身没有稳定图标，强行压成图标会降低可理解性。
- 不修改 Tailwind 断点基线。当前项目明确是 PC-only，直接改断点会影响所有 `md/lg/xl` class，风险远大于这次左栏响应式目标。

## Risks / Trade-offs

- [Risk] 收缩阈值固定后，个别介于阈值附近的宽度可能仍需后续微调。→ 使用集中 CSS 变量和 media query，后续只需调整一个断点。
- [Risk] hover 展开时覆盖中间内容。→ 这是本需求要求的“附在页面上”；内容 offset 保持 rail 宽度，避免 hover 导致布局跳动。
- [Risk] 历史记录在收缩态不可直接选择。→ rail 的目标是释放空间并保留核心入口，历史记录在 hover 展开后仍可访问。
