## Context

动作编排页 `ActionComposerPage` 当前包含三个主要区域：顶部紧凑工作台、中央编排区和右侧动作库。已保存编排现在通过顶部“已保存”按钮展开下拉列表，列表内部已经复用 `RoutineCompositionCard` 支持打开、复制和删除。

这次调整只改变入口位置和展示方式：已保存编排仍使用现有 `WorkoutRoutine` 数据、现有客户端 API 和现有卡片操作，不引入新的持久化或查询契约。

## Goals / Non-Goals

**Goals:**
- 让右侧栏成为动作编排页的素材入口，顶部可在动作库和已保存编排之间切换。
- 保留动作库现有搜索、筛选、详情和添加动作能力。
- 已保存编排以纵向卡片列表展示，复用现有打开、复制、删除能力。
- 移除顶部“已保存”下拉，减少顶部工作台操作密度。

**Non-Goals:**
- 不改变训练编排保存、读取、复制或删除 API。
- 不改变动作库筛选参数、分页策略或详情抽屉。
- 不调整移动端布局；当前动作编排页右侧栏仍以 PC 端为主。
- 不新增批量管理、排序或搜索已保存编排能力。

## Decisions

### 1. 使用右侧栏 tab 管理素材视图

在右侧栏顶部增加本地状态 `rightPanelView`，取值为 `library` 或 `saved`。tab 只控制右侧栏内容展示，不影响当前编排区状态。

取舍：继续保留顶部下拉会让同类素材入口分散；改为右侧栏 tab 能把“添加动作”和“打开已保存编排”放到同一个工作区内，同时不需要改动数据层。

### 2. 复用现有 `RoutineCompositionCard`

已保存视图直接复用当前下拉里的 `RoutineCompositionCard`。打开编排后保持当前 `openWorkoutRoutine` 逻辑，复制和删除继续使用现有函数。

取舍：重新设计列表项可以更贴合右侧栏宽度，但会复制估算、状态和操作按钮逻辑。复用现有卡片能保持行为一致，样式只做容器级适配。

### 3. 顶部工作台只保留当前编排操作

顶部工作台继续保留新增、导入模板、保存和指标展示，不再展示已保存入口。已保存数量通过右侧 tab 徽标表达。

取舍：顶部保留已保存入口能减少一次 tab 切换，但会让同一功能在两个地方出现。统一入口更清晰，也符合用户提出“把已保存按钮也放在右侧”的方向。

## Risks / Trade-offs

- [Risk] 用户打开已保存编排后仍停留在已保存视图，可能想继续添加动作时需要切回动作库。→ Mitigation: tab 状态显式可见，打开编排不自动跳转，避免用户刚选择的列表消失。
- [Risk] 右侧栏宽度较窄，卡片操作按钮可能拥挤。→ Mitigation: 复用现有紧凑卡片，并确保标题、指标和时间使用 truncate。
- [Risk] 删除当前激活编排后右侧列表和顶部状态不一致。→ Mitigation: 继续沿用现有删除逻辑清理 `activeWorkoutRoutineId`，不改状态事实来源。
